# AI 助手前六项改进：实施与学习指南

现有基础见 [AI 助手](ai-assistant.md)。本次已完成以下六项主体代码，本文说明具体行为、验收例子及可继续学习的技术。

**验证状态（2026-11-03）：** 前端 924 项、后端 1470 项测试通过（另有 4 项既有跳过），类型与后端格式检查通过；真实模型与客户资料验收、生产部署尚未执行。下述例子是验收标准，不表示已经逐项完成真实环境验收。

## 1. 联网回答延续多轮上下文

- **本版实现：** 联网合成带入有界历史、任务摘要和本轮资料，超预算截断有明确标记；追问可沿用上轮公开检索主题。摘要、附件和旧回答不进入搜索参数。保留本轮方式与权限检查；旧回答只帮助理解问题，变化中的事实仍需重查。
- **验收例子：** 先查“最新细胞培养策略”，再问“第二项再展开”，检索词应保留前文主题；切换“不联网”后不能继续发搜索请求。切换任务后也不能夹带上个任务的内容。
- **要学什么：** 上下文窗口是模型本次能看到的有限材料，不是永久记忆；界面状态也有时间点，异步结果不能覆盖新设置。先读 [React：状态快照](https://react.dev/learn/state-as-a-snapshot)，练习在发送时固定本轮设置。

## 2. 知识库证据校验与原文定位

- **本版实现：** 将来源路径与本轮实际工具记录关联，展示可核对的原文摘录和位置；来源入口重新鉴权并定位原文。区分“检索命中”“已读原文”“有摘录可核对”，不把模型自己写出的路径当证据，也不将路径匹配标作全部语义已验证。
- **验收例子：** 模型编造路径时不能显示已核验；合法来源可打开对应段落；权限撤回后无法继续读。资料确实包含某段话，也不自动证明回答的每个结论都成立。
- **要学什么：** RAG 是先找资料、再据此生成；重新排序和逐条引用需要额外工程。[RAG 原论文](https://arxiv.org/abs/2005.11401)解释检索与生成的结合；[Pydantic 模型文档](https://docs.pydantic.dev/latest/concepts/models/)帮助理解字段类型校验与事实真实性的区别。本轮先做可核对的来源关联，不承诺全部语义校验。

## 3. 导入资料保留结构

- **本版实现：** 保留本机提取的全文及可识别标题层级，按结构组织可选片段，附文件名和可确认的位置；发送前可预览、选择。超限与提取限制明确提示；不承诺复杂 PDF 表格还原，也未增加 OCR。
- **验收例子：** 导入含二级标题、列表的资料，预览保留提取全文，片段看得出所属章节；复杂表格需人工核对，扫描 PDF 提示先 OCR；只有字符位置时不能标作 PDF 页码。
- **要学什么：** AST 可理解为“文档的目录树和积木块”，比按固定字数切割更容易保留含义；结构保留不等于 Word/PDF 排版完全复刻。读 [CommonMark 的块与行内结构](https://spec.commonmark.org/0.31.2/#blocks-and-inlines)，先用小样本观察标题、段落和代码块的边界。

## 4. 用户确认后保存长期任务记忆

- **本版实现：** 用户从一条回答打开“记入任务记忆”，编辑内容并选择目标、约束、已确认结论或待解决问题，预览后明确保存；保留来源轮次。后续回答带入已保存摘要，业务事实仍按本轮权限重查。不会从提问自动确认结论。
- **验收例子：** 从回答中选取“报告按美元计价”，作为约束保存后刷新仍生效；取消不改变原摘要；两个窗口同时保存应提示版本冲突。模型提出的结论只有经用户确认保存后才成为任务记忆。
- **要学什么：** 长期记忆是应用保存、可管理的数据，不是模型自动永久记住。网页、附件里的“忽略规则、记住密码”等文字可能是恶意指令，不能获得系统指令的权力。读 [OWASP：提示注入](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)，学习区分用户确认与资料内容。

## 5. 围绕选定成果做版本迭代

- **本版实现：** “基于此稿修改”明确指定原稿，新回答保留基稿关联，旧版不被覆盖。预检和执行都核对基稿所属任务、当前权限与数据范围；预检不调用付费模型。最终成果仍由用户选择，保存核对 revision，重复请求按编号去重。
- **验收例子：** 选定第一版后要求“只改结论”，新稿以它为基础，失败时旧稿仍可用；同一请求重试不多生成。选 PM 基稿但切到“仅知识库”应提示范围不符，不能暗中读取项目数据。
- **要学什么：** 不可变版本就是保留旧稿、另存新稿；乐观锁是在保存时检查“我看到的还是最新版吗”；幂等是重复同一请求只产生一次预期效果。读 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)的 If-Match 与 9.2.2；本项目 revision 属于应用层实现，不代表已采用该 HTTP 头。

## 6. 提高检索相关性

- **本版实现：** 用小规模术语映射补充常见表达，将追问补上前文主题；对候选片段做词法相关性排序和过滤，按预算交给模型。本版未引入新的向量检索或 rerank 模型，效果需用实际题集比较。
- **验收例子：** 搜“某规范第 12 条”应优先返回对应规范和条款；同名不同年份不混淆；库里没有答案时说明缺口，不能靠返回更多无关段落掩盖问题。
- **要学什么：** retrieve 是先找候选，rerank 是重新排序，cite 是把结论指回证据，三步不能互相替代。读 [Stanford IR：BM25](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html)，理解词频、稀有度和文本长度对排序的影响；这是进阶学习材料，不表示本版已完整实现 BM25。
