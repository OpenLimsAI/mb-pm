# MDM 项目整合：第一阶段

2026-10-26，实施范围为绑定已有项目。MDM负责登记/治理及唯一关联，PM负责执行；双方ID保持不变，严格一对一，阶段/工作包属于PM WBS。

## 实施清单

- [x] 增加受当前PM身份和项目可见范围保护的项目只读引用接口，不新增跨库数据写入。
- [x] 增加服务端受控 MDM_PUBLIC_URL（默认空）与MDM入口；门户入口不授予MDM权限，不伪装统一登录。
- [x] 项目页提供含PM项目ID的MDM深链；MDM依据其唯一映射解析登记项目，未绑定时明确提示。
- [x] 目标URL仅由受控配置构造，拒绝凭据、查询串、fragment、不安全协议；不接收任意返回URL、不在URL传令牌。
- [x] 使用既有临时SQLite、合成RSA身份和HTTP替身验证接口、权限、项目失效与深链安全；运行适用前端测试、类型检查和构建。

本轮不改Casdoor客户端、账户、角色、凭据和会话协议；不下线cmab-hub，不迁移已有业务库，不自动创建项目或双向覆盖状态、计划、团队、预算。MDM访问PM的只读身份留空关闭，另行批准和配置后才做真实联调；现有PM令牌不会被当作MDM通行证。

MDM实施契约见同级cmc-platform/cmab-mdm-platform/docs/decisions/2026-10-26-pm-project-link-phase1.md。回退时移除本阶段入口与接口，映射由MDM保留；本仓不创建第二份可写映射。本地实现、隔离测试、真实登录联调、数据库迁移和部署状态分别记录。

## 本轮验证与合并门槛

TDD：只读引用/范围/深链9项先失败后通过；门户MDM卡片2项先失败后通过；新增门户受保护入口测试先发现缺少响应类导入，修复后门户与接口54项通过。没有把合成RSA签名或HTTP替身算成真实Casdoor登录。

本地：临时SQLite全量292项通过；另建tmpfs PostgreSQL全量292项通过，原CI指定覆盖率范围93.93%。前端41项、既有逐文件90%覆盖率门槛、门户路由、tsc和Vite构建通过。后端全app ruff 0.7.0格式检查通过，新增MDM服务lint通过；核实financeDraft.ts与HEAD一致且无用户未提交修改后，用等价字符码判断修复原lint错误；追加34项控制字符/金额回归通过，全量eslint无错误（本机coverage生成文件3项告警）。FastAPI旧路由存在B008存量告警，新路由使用Annotated依赖。

MDM增加独立容器测试工作流，覆盖从空PostgreSQL库到0066迁移、一对一并发与冲突、数据库双侧唯一约束、权限、审计和就绪；这仍不是浏览器E2E。

当前硬阻碍：尚未批准/配置隔离Casdoor客户端和验收身份，尚未实际从门户登录进入MDM、绑定成功后刷新再进入、跳至正确PM执行项目并验证未授权用户。草稿PR不得转就绪或合并，自动测试与CI不能替代这一步。现有账号、客户端、安全配置、Hub和生产服务保持不动。

## 待批准的真实验收操作

仅本机127.0.0.1新建Casdoor:8018和全新空数据库；不复用现有账号。创建两个本地OIDC客户端cmc-pm-phase1-e2e、cmc-portal-phase1-e2e，回调分别为http://127.0.0.1:5189/api/v1/auth/callback、http://127.0.0.1:5189/api/v1/portal/callback，登出回跳限http://127.0.0.1:5189/login。MDM仍用独立密码登录，不新增MDM OAuth客户端。

创建隔离验收管理员、只加入两个合成项目且无任务的rd核验用户、无项目范围用户；MDM用新隔离库的管理员和只读用户。核验用户的实际PM audience访问令牌最多1小时、无自动续期，仅注入临时后端容器环境，不进仓库/日志/浏览器URL。它是普通用户身份，不是严格只读机器角色；正式机器身份方案另行批准。反向页面深链无需后端凭据。

所有身份/口令/客户端密钥限该空实例与临时容器。验收后退出会话、删除本次容器/数据库/身份配置。计划浏览器入口：MDM http://127.0.0.1:5188/mdm/，PM与门户 http://127.0.0.1:5189/。在批准前这些地址不代表已经启动或验收。

## 兼容顺序与回退

推荐PM新增受保护的只读引用接口先合入，再合MDM；MDM_PUBLIC_URL与PM核验配置默认空，不因合并自动启用。先分别确认两仓最新head CI，再完成真实E2E后才允许合并。没有生产部署授权；若发现合并触发自动部署，需先明确部署影响。

回退优先清空新入口/核验配置，保留映射数据。MDM带映射时拒绝降级删表；旧代码的迁移版本就绪检查意味着不能无协调直接退代码或stamp版本。PM不保有第二份映射，原项目状态/预算/团队不会被整合链路覆盖。
