# 知识报告应用

[返回 README](../README.md) · [开发与测试](development.md) · [配置](configuration.md)

知识报告在门户 `/solutions` 独立挂载，包含「报告撰写」「知识库资料」「AI 研究助手」三个模块。点击工作区上方「排列布局」，上栏选择带 1、2、3 编号的排列图，下栏按顺序选择模块填入编号位置；选齐三个后点击「应用排列」。可点击已选模块取消并重新编号，或「重置顺序」后重新选择；取消不会改变当前布局。

| 排列方式 | 1 号位置 | 2 号位置 | 3 号位置 |
| --- | --- | --- | --- |
| 横向三个 | 左 | 中 | 右 |
| 左一右二 | 左整列 | 右上 | 右下 |
| 左二右一 | 左上 | 左下 | 右整列 |
| 上二下一 | 左上 | 右上 | 下整行 |

三个模块分别可以隐藏；顶部保留对应的展开入口，其余模块使用腾出的空间，全部隐藏也能恢复。应用新排列时会展开三个模块。排列和隐藏偏好仅保存在当前浏览器，不写入报告正文或触发报告保存。窄屏按所选的 1、2、3 顺序纵向展示，保证每个模块可操作；回到宽屏会恢复选定排列。

报告撰写标题栏中的「目录」按钮可隐藏或展开章节目录，目录与正文之间的分隔线支持拖动调宽，也可聚焦后按左右方向键，Home / End 跳到最窄 / 最宽。偏好宽度为 160–360 像素，窄模块中会限制目录占比为正文留出空间；隐藏、恢复及重排保留章节、正文和配方展开状态。目录宽度与显示偏好随浏览器保存。

产品依据为 2026 年 10 月 23 日《MBERP 知识方案应用业务需求文档》v0.1，及后续章节与布局反馈。

## 使用流程

1. 从工作台进入「知识报告」，新建报告或打开已有报告。填写项目、产品及章节；复制已有报告会创建新记录。
2. 在「报告撰写」模块编辑章节及配方表，保留物料、用量、单位、计量基准和选择理由。保存状态区显示正在保存、已保存或失败；发生版本冲突时先保留草稿，再重新载入比较。
3. 「知识库资料」默认展示原知识库的资料视图：搜索、文件夹、标签、上传、正文阅读与笔记沿用原功能及权限，去掉重复的问答和 AI 设置入口。窄栏可在资料库与阅读之间切换。选中文献后可「加入问答范围」或「引用到章节」；「报告资料」页签保留个人录入的实践记录、专家笔记与既有资料。
4. 输入问题，选择资料范围和可见的写作上下文。问答仅检索所选资料；点击依据查看原文后，预览并手动插入章节。没有配置模型时提供真实检索摘录，明确标记为资料检索，不伪装成 AI 生成。
5. 提交评审时选择评审者；也可由作者确认并保留明确标识。定稿后正文冻结，后续修改建立新版本；支持 Word 导出与主动发布为个人知识资料。

章节目录支持添加、修改名称和删除，窄屏也保留操作入口。修改名称只更新该章节标题，不改变正文与引用；名称去首尾空白后不能为空，最多 200 字。删除前显示确认，至少保留一个章节。删除章节会同时移除其引用和配方中的相关依据绑定，受影响配方项回到待验证；其他章节及历史问答保留。可撤销最近一次章节删除，恢复章节与引用而不覆盖其他章节后续编辑。以上编辑操作仅对可编辑草稿开放，沿用自动保存与版本冲突保护。

## 数据与权限

生产模式经 `/api/v1/solutions` 保存到应用数据库，不依赖浏览器草稿作为正式记录。报告以已验证的 IAM 发行方及用户隔离，写请求检查门户 Origin；自动保存使用修订号，过期提交返回冲突，不能静默覆盖。评审与快照对应确切版本，问答历史默认作者私有。

首版以个人报告和指定评审为边界。项目名称为报告标签，不代表继承 PM 项目成员权限；报告应用不提供任意团队共享、多人实时合编或生产配方下发；附件上传与解析在原知识库中按其功能及权限执行。内部定稿不替代企业生产及质量流程。原始 BRD 中的项目自动关联、完整附件管理及更复杂协作需要继续建设。

手动资料保存在报告应用的个人知识集合。定稿发布也先保存到该集合，不自动写入外部 DIKW；引用、版本与原始报告保持关联。含企业知识库依据的报告首版不能发布到个人集合，以免脱离原始访问权限。这与外部企业知识库只读连接分开。

## 企业知识库连接

资料视图通过固定知识库入口的 `?embed=library&parentOrigin=...` 嵌入，等待专用视图的 ready 消息后才显示；旧版知识库、网络或登录未完成时给出重新加载和新窗口登录入口，不能只隐藏外层样式假装移除了 AI。必须配套知识库的 `library-embed` 版本；当前仅本地预览，生产代理的 frame 策略与真实登录还未验收。

门户 Cookie 不能充当独立 KB 应用会话。后端使用固定的 DIKW Core 连接，并在每次企业资料访问时向 IAM 实时确认 KB 角色。平台管理员身份不会自动取得知识库权限；入口目录缓存不用于资料授权。

原知识库的浏览与管理使用自己的 BFF 和权限，不依赖以下报告适配变量。将资料用于报告引用或 AI 问答仍需要这些连接配置；iframe 消息只传路径和标题，不传正文、令牌或可信引用，也不会把企业原文转存个人集合。

后端进程可配置以下环境变量，不得带 `VITE_` 前缀：

| 变量 | 作用 |
| --- | --- |
| `SOLUTION_KB_CORE_URL` | 固定的 Core 服务地址，不允许用户提交任意代理地址 |
| `SOLUTION_KB_TOKEN` | 服务端 Core Bearer 令牌，仅由运维注入 |
| `SOLUTION_KB_PUBLIC_URL` | 用户可打开的知识库页面地址，示例为 `https://kb.openlims.ai` |

参见后端示例配置。连接未配置时仍可撰写和使用手动资料，界面明确提示企业知识库尚未连接；不能据此声称已检索企业论文。外部检索错误与无结果分开返回。

问答使用现有工作台/项目管理 AI 服务商配置，不复用 KB Agent 的会话或配置。配置缺失返回资料检索模式；配置存在但服务调用失败则报告错误，不能自动伪造回答。用户选择资料的限制在后端执行，写作上下文可用于缩小检索问题，但不被当成文献证据。模型调用超时为 60 秒；包含企业资料读取的整个问答请求最长等待 5 分钟，超时会保留问题并显示重试入口。

## 界面预览与正式运行

开发预览使用 `/solutions?preview=1`，要求 Vite 开发模式且 `VITE_USE_API=false`。预览资料、论文和实验均明确标注为演示，不代表真实科学结论；编辑保存在当前浏览器的隔离预览空间，不触发模型、IAM 或企业库调用。生产构建不开放此预览绕过。原知识库界面预览另需在 KB 仓库以 `KB_LIBRARY_PREVIEW=1 npm run dev` 启动 4322 端口；独立进程的示例库支持文件夹、手工标签、阅读、笔记和 Markdown 演示上传，PDF / Office 解析及模型能力不伪装成功。启动方式见[本地知识库入口](development.md#本地知识库入口)。

正式运行使用 `VITE_USE_API=true`，通过门户 IAM 登录。空数据库不会自动注入演示报告；新建报告和手动资料由用户操作产生。发布前必须执行数据库迁移或确认现有初始化流程建立新增表，并核对模型配置、KB 连接、备份和真实账号权限。
