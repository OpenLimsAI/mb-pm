## 使用

1. 工作台进入「行业信息」→「信息源」。首次为空库，默认 ICH 四类、每日频率，监控关闭。
2. 系统管理员或知识库负责人点击「检查更新」，逐类读取 Q 质量、S 安全性、E 有效性、M 多学科官方目录。检查成功只代表发现文件。
3. 「批量收录」选择范围和真实目标文件夹（或信息获取原文归档）、勾选资料、提交任务。可新建共享 KB 文件夹。
4. 后台保存 PDF、校验 SHA256、提取正文；选择「保存后建立知识库问答索引」时再启动 Core 索引。归档、解析、索引分别显示结果，离开页面不影响执行。
5. 在「知识资料」按名称或正文搜索，查看归档原件、正文及历史版本。两版以上可比较最近两版正文；只有真实索引完成才显示可问答。
6. 需要持续检查时在来源设置选择文件夹并开启监控。默认每日、可选每周；定时检查也重新校验已知 PDF，识别同 URL 内容替换。首次基线合并通知，避免逐篇刷屏。
7. 成员在「我的关注」订阅来源、分类或文件；收件箱已读、稍后看、提醒频率与笔记按个人身份持久保存。每日汇总是应用内待阅读口径，没有外发邮件、短信或定时推送。

## 权限与真实性

所有接口复用门户会话、强制改密和经验证发行方/组织/subject；每次请求及后台步骤实时核对 IAM，`admin` 或 `kb_manager` 才可管理，其他成员只浏览、搜索、订阅。写入须同源。后台权限失效暂停，负责人可在运行记录续跑或重试检查，不借用其他账户执行。

正式界面只读服务端真实数据，不使用演示兜底。`VITE_USE_API=false` 下 `/information?preview=1` 保留独立内存演示；预览不能执行真实采集。

来源仅适配 ICH 官方四类公开 PDF。其他来源可登记但显示待适配，不能启动采集。网络请求校验 HTTPS、官方主机、公开文件路径、重定向与 DNS 地址，遵守 robots，限制速率、超时与大小。不会绕过登录、验证码或访问控制。

## 数据流程与恢复

PostgreSQL `information_entries` 保存团队元数据/任务/个人偏好，`information_texts` 单独保存正文，`information_leases` 协调两个实例。原文按租户和 SHA256 写入共享目录（0600）；刷新接口不携带长正文。任务逐项落盘，网络瞬时失败有限重试，暂停/重启保留进度；恢复须重新核对权限。

文件校验值相同不产生重复版本；目录元数据变化、原文件变化分别记录。原件变化但规范化正文相同归为格式变化，可按个人偏好隐藏。正文比较有截取上限，不代替正式法规差异审查。

签名服务桥接仅允许目录、建文件夹、公开 ICH PDF/正文入库和状态查询；HMAC 绑定时间、nonce、正文摘要并拒绝重放。KB 独立实时核对管理身份，使用原有 Core 凭据和公开客户端接口，原件资产与正文一起入库，文件夹关联真实保存。已删除论文不自动恢复。正常 KB 上传/AI 权限不因此放宽。

## 范围和限制

- 单 PDF 25 MiB，原文配额默认 5 GiB；磁盘不足保留失败原因。正文最多 1000 页/200 万字符，页面显示前 20 万字符，差异最多 4 万字符。当前支持有文本层 PDF，扫描件或加密件保留原件并明确提示 OCR/解密前提，不假装解析成功。
- 本次采集不调用云端大模型。知识库索引使用已有嵌入配置，问答/翻译沿用 KB 已配置服务，可能按该服务计费；费用测算是可调假设，不是实际账单。没有自动 AI 摘要或法规解读。
- Core 当前无公开版本停用接口，历史采集版本以独立知识资料保留。全库问答可能同时检索到历史版本；核对来源日期，或从当前版本进入单篇问答。不能声称默认只使用最新版。
- 来源被撤回或本轮超时不会删除已存原文，也不能据此断言没有更新。单源同一时刻只运行一个任务。目录刷新、任务结果与个人偏好持久化；最近 500 条事件/100 个完成任务展示，活跃任务始终显示。
- 默认监控关闭，上线本身不启动全量采集。一般成员的信息获取阅读权限不自动授予知识库访问权。
