# 功能说明

[返回 README](../README.md) · [配置与权限](configuration.md) · [架构说明](architecture.md)

本文记录当前代码的功能、入口和使用边界；环境发布及验收状态见 [部署交接简明](部署交接简明.md)。

## 员工应用门户

门户入口为 `https://www.openlims.ai`，提供迈博药业登录界面及项目管理、知识库应用卡片。
`pm.openlims.ai` 保留项目管理，`kb.openlims.ai` 是外部知识库系统。

| 页面 | 路由 | 用途 |
|---|---|---|
| 企业登录 | `/login` | 在本页输入用户名和密码登录（提交到 IAM，不跳到 IAM 登录页） |
| 应用工作台 | `/` | 查看应用准入及打开应用 |
| 我的设置 | `/settings` | 查看登录身份、修改用户名和密码、查看应用访问（所有人）；旧 `/account` 跳转至此 |
| 账号管理 | `/accounts` | 组织成员名单与账号维护：系统管理员可改，项目负责人只读，员工看不到（见下文） |
| 版本更新 | `/release-notes` | 应用功能说明与历史更新，所有登录用户可查看 |
| 使用帮助 | `/help` | 登录、权限与退出说明 |
| 应用跳转 | `/launch/pm`、`/launch/kb` | 验证准入后打开固定应用 |

共 6 个用户页面（登录、工作台、我的设置、账号管理、版本更新、帮助）和 1 类应用跳转页；`/workspace` 在门户兼容跳转至首页，`/account` 跳转至 `/settings`。
PM 域名的 `/workspace` 返回正式门户，PM 首页及 `/dashboard` 保留项目总览。PM 顶栏通过浅金色「应用工作台」入口返回门户，知识库统一从工作台打开；侧栏不再显示「相关系统」，品牌区移除无权限含义的固定 CTO 标签。组织管理与个人设置属于工作台，PM 侧栏保留「AI设置」（`/ai-settings`，限系统管理员 / 项目负责人 `cmc_lead`）。PM 的 `/settings` 和顶栏姓名打开门户「我的设置」，`/org` 跳到门户「账号管理」；门户与 PM 的旧 `/settings?tab=ai` 均跳到项目管理 `/ai-settings`。
登录页直接输入用户名和密码：浏览器把它们提交到 IAM 的登录接口换取一次性授权码，再走原有回调建立会话，密码不经过本系统后端，也不再跳到 IAM 登录页；IAM 同时写入自己的登录会话，从工作台进入项目管理 / 知识库仍是单点登录。已在其他应用登录过（浏览器里有 IAM 登录会话，如从项目管理点自己的名字进入门户）时，登录页直接用该会话完成登录，不再要求输入密码，也不经过 IAM 页面。错误提示（如密码错误、剩余尝试次数、账号停用）由 IAM 返回并显示在本页；浏览器连不上 IAM，或账号需要两步验证等 IAM 页面上的步骤时，自动改为跳转 IAM 登录页。项目管理的登录页（`pm.openlims.ai/login`）相同。不提供自助注册与密码找回，忘记密码由系统管理员在「账号管理」中重置；其余 IAM 设置仍在 IAM 管理台。

门户不拉取项目业务数据：`/api/v1/portal/me` 获取身份与应用清单，`/api/v1/portal/username`、`/password` 用于「我的设置」，`/api/v1/portal/accounts` 用于账号管理（仅系统管理员 / 项目负责人）。
打开 PM 时经 `/api/v1/auth/login?return_to=%2Fdashboard` 建立 PM 会话；KB 在新标签页打开，由知识库自身验证身份。
项目管理默认对组织内所有人开放，门户目录本身不建成员；第一次进入项目管理时自动建成员。知识库按 KB 角色显示是否开通。
应用卡片的状态不能代替各应用的数据和操作权限检查。

### 账号管理

当前登录用户在账号列表中以蓝底白字「登录账号」标识、浅蓝行背景和左侧蓝色竖线突出；按实际 IAM 登录身份识别，姓名相同的其他账号不会标记。

IAM 的简化版，也是全公司账号与组织成员的**唯一修改入口**：在这里改就是改 IAM，在 IAM 管理台改的内容刷新后也会出现在这里。项目管理不再提供「组织」页，组织成员名单只在这里查看（仅系统管理员和项目负责人可见；员工打开此地址只看到无权限提示，不加载名单）。

「资料与身份」分为公共资料、平台管理身份、项目管理、知识库四块。平台身份单独选择普通成员或系统管理员；PM 业务角色只有员工、项目负责人。系统管理员继承 PM 全部权限，知识库编辑授权单独设置，不因平台身份变化而增加或移除。

| 平台身份或业务角色 | 项目管理 | 账号管理 |
|---|---|---|
| 系统管理员（IAM `admin`） | 全部权限 | 可改所有人的所有信息 |
| 项目负责人（IAM `cmc_lead`） | 编辑项目（项目信息、预算与 WBS 结构）、删除项目等重要编辑（全部项目） | 只能查看 |
| 员工（不分配项目管理角色） | 日常录入：更新自己负责的任务（进展、状态、实际日期、工时、花费） | 看不到 |

- 知识库只允许选择「可编辑」（`kb_editor`），「仅阅读」置灰，后端拒绝写入 `viewer`。新账号默认可编辑；旧 `kb_viewer` 账号保留只读，打开面板或只改其他资料不会自动升级。缺少角色时进入显式编辑流程，不通过修复账号顺带赋权。
- 旧 `project_lead` 保留「本人项目」说明，`production` / `qa_qc` 保留实际角色；未主动修改 PM 业务角色时不改写，同时持有多个角色时按最高的生效。取消其他人的平台管理员身份后，PM 回落到保留的业务角色，没有则为员工。
- 管理工作台（`dikw-admin`）不在账号管理里维护，到 IAM 管理台分配。

入口在门户导航和工作台独立的「管理功能」版块；「工作应用」只放项目管理和知识库，账号管理采用较紧凑的横向入口，管理区使用独立的浅灰蓝底色。只有系统管理员和项目负责人看得到管理版块，普通员工及界面预览不显示；接口每次请求都向 IAM 实时核对身份，操作人还须有有效的项目管理成员（用于审计）。

| 操作 | 谁能做 | 说明 |
|---|---|---|
| 账号列表 | 系统管理员、项目负责人（只读） | 直接读取 IAM，平台身份、PM 角色、知识库分别成列；管理员的 PM 权限标记为继承 |
| 新建账号 | 系统管理员 | 分别选择平台身份、PM 业务角色及 KB 编辑权限，维护资料与初始密码，同时建立 PM 成员；首次登录须改密，密码仅在完成页显示一次 |
| 编辑 | 系统管理员 | 保留资料与身份、用户名、重置密码、停用 / 删除四页；权限分区、变更摘要及关闭未保存修改确认 |
| 修改用户名 | 系统管理员 | IAM 账号、角色成员与项目管理成员一起改名 |
| 重置密码 | 系统管理员 | 新密码输入两次（或自动生成），设为临时密码；对方已登录的会话立即失效，下次登录须在门户 / 项目管理内修改 |
| 停用 / 启用 | 系统管理员 | 二次确认；IAM「禁止登录」与项目管理成员一起切换，项目管理立即生效；停用时对方在门户与项目管理的登录会话一并结束 |
| 删除 | 系统管理员 | 须输入用户名确认；先移出全部角色再删除 IAM 账号（Casdoor 删除时不清理角色成员）；项目管理成员只停用，历史保留 |
| 需要处理 | 系统管理员 | 列出知识库未开通、项目管理成员被停用、同名成员已关联其他账号、IAM「添加」留下的默认账号、只有项目管理成员没有 IAM 账号（历史数据）等问题，可一键修复或跳转处理 |

- 在 IAM 管理台直接建的账号，第一次进入项目管理时自动建成员（按员工），不需要预置。
- 项目管理里不能增删改成员（后端对应接口返回 410），旧 `/org` 链接跳到这里。
- **首次登录 / 重置后改密在应用内完成**：新建或重置后，对方登录门户或项目管理时先看到「请先修改临时密码」页，须输入临时密码和新密码（两次）；改完前后端对其他接口返回 403（含 Bearer 访问）。不使用 Casdoor 的「需要更新密码」开关——3.100.0 打开它后登录会被带到 IAM 自己的「我的账户」页、回不到应用；若有人在 IAM 管理台打开了它，「需要处理」会提示，点修复改为应用内改密。知识库等其他应用直接登录时不强制改密。
- 门户与项目管理里不再提供进入 IAM 管理台的链接（登录页、门户页首、设置、使用帮助均已移除）；修改用户名 / 密码在门户工作台「我的设置」中进行（点项目管理顶栏自己的名字也会打开这里），忘记密码由系统管理员在账号管理中重置。
- 在 IAM 管理台直接改姓名、用户名，或停用、删除账号，项目管理成员名单按 IAM 自动同步（登录时，以及打开账号管理或项目管理加载成员名单时对账，名单加载每分钟最多一次）；删除的账号对应成员只停用，历史保留。
- 平台身份与 PM、KB 业务权限调整后应重新登录对应应用；门户入口目录同步本次保存结果，但不能代替业务鉴权。只改 KB、平台身份或公共资料不自动创建 PM 成员；主动维护 PM 角色或档案时才关联或创建。停用对项目管理立即生效。
- 不能取消自己的系统管理员身份、停用 / 删除自己或重置自己的密码；IAM 组织管理员（`isAdmin`）账号只能在 IAM 管理台停用、删除、改名和重置密码。
- IAM 中尚未建立的角色在界面上禁用，接口在创建任何数据前拒绝。
- 操作写入审计日志（新建账号、修改账号、修改用户名、重置密码、删除账号、修复账号），记录操作人和修改前后的身份，不记录密码。
- 账号管理写操作通过共享数据库锁串行处理 IAM 角色成员列表；保存后回读校验，IAM 中途失败或本地保存失败时补偿本次修改，补偿失败则明确提示核对。该锁不约束 IAM 管理台的外部写入。

## 项目管理模块

### 首页

入口：`/`（PM 域名），`/dashboard`（本地及 PM）。

管理者（admin / cmc_lead / project_lead）默认**项目组合总览**，可切换到「我的看板」；研发 / 生产 / QA 登录后直接进入**我的看板**（个人 KPI + 本周负荷、Kanban 三列、待办、参与项目，点任务即可录入进展）。项目组合总览：组合 KPI（在研项目 / 总进度 / 待达里程碑 / **风险项** / 关键路径 / 预算执行）、**风险预警**（拆分为「进度风险」与「质量与合规风险」两族，质量门里程碑可派生、偏差/CAPA/批次留有接入位）、项目健康度红黄绿分组卡片。

### 项目

入口：`/projects`。

项目列表（卡片 / 表格 / 组合矩阵）+ 右上角 **模板管理** 入口（→ `/templates`：模板目录 / 新建（空白·复制）/ 可视化结构编辑器 / 甘特预览 / 导出 / 删除）+ **从模板创建项目**（向导第 3 步可增删任务）+ 项目详情：**概览**（里程碑路线图 + **预算与成本卡**）、**WBS**（行内编辑表格 / 树 / 甘特，状态·进度·计划起止·**负责人改派**·**任务预算**均行内即改即存并汇总；负责人只能选项目团队成员）、**里程碑**（达成条件 ↔ WBS 任务关联）、**延迟推演**（选定任务 + 延迟天数，沿依赖链推算受影响任务 / 关键路径 / 里程碑与项目完工顺延，只推演不改计划）、**基线对标**、**团队**（「管理成员」中现有成员均已勾选；任务只能派给团队成员——负责人下拉、编辑页任务表单、推荐负责人都只列团队成员，其他人先在这里加入；仍负责或协作任务的人锁定、不能移出，先在 WBS 转交任务；升级时有任务但不在名单里的人自动补入团队，导入与复制项目同样自动带入）；详情页右上角 **编辑项目**、**删除项目**（删除仅系统管理员 / 项目负责人，输入项目编号二次确认，连同子项目 / 任务 / 依赖 / 团队 / 财务 / 基线一并删除，成员账号保留）。

- **编辑项目**（详情页右上角、删除项目左侧；系统管理员 / 项目负责人，旧角色 `project_lead` 限本人负责或参与的项目）：一个入口同时修改预算与项目结构。上方「预算与成本」卡内直接填写总预算、已承诺、成本结构、财年和备注，不再打开预算弹窗；预算与下方项目信息、结构修改一并点击「保存修改」提交，取消时一并放弃。下方结构编辑与模板结构编辑同一套界面和用法——增删改子项目、任务 / 里程碑和前置依赖，先记在草稿里，点「保存修改」一次性生效（后端一个事务，写审计日志）。编辑期间他人改过项目总预算、已承诺、成本结构或结构（计划日期、负责人、任务预算、依赖等）时保存会被拒绝并提示重新载入，日常录入进度不受影响。已开始（状态不是「未开始」、进度 > 0 或有实际日期）或已录实际花费的任务不能删除，含这类任务的子项目也不能删除；改日期不自动顺延后续任务，与前置冲突时行内提示，可一键改到前置结束之后。状态、进度、实际日期与实际花费仍在任务详情或「表格录入」中填写。离线演示模式不可用。
- **任务插入与手动排序**（编辑项目与模板结构编辑相同）：鼠标移到任务行上，行上沿出现「＋」，可在任意两个任务之间插入（不预设前置依赖；项目中开始日期默认接在上一个任务之后），编辑 / 新建任务时「前置依赖」默认展开；拖动行左侧手柄调整顺序，可拖到其他子项目，选中手柄后也可用 ↑ ↓ 键移动。WBS 树形、表格录入、甘特图都按这一手动顺序显示；升级前的任务按原显示顺序（计划开始、编号）自动编号，用模板创建的项目沿用模板中的先后。
- **项目与子项目层级**（编辑项目）：顶部「Lv1」行可修改项目编号与名称（仅项目负责人或系统管理员 / CMC 负责人；编号不能与其他项目重复）；改编号时，以原编号开头的任务编号默认一起换成新编号，可取消勾选。子项目（Lv2）与任务一样：头部上沿「＋ 子项目」可在任意两个子项目之间插入，拖动头部手柄（或选中后按 ↑ ↓）调整顺序，其下任务整体跟随。模板结构编辑中子项目同样可插入、拖动。
- **项目计划起止**：项目详情页首、项目卡片与表格显示的起止按任务实时计算（最早计划开始 → 最晚计划结束），任务怎么调就怎么变；没有任务时沿用项目创建时的计划起止。新建基线、基线对照、复制项目的日期平移与 AI 分析使用同一起止。
- **复制项目**（项目列表右上角；仅系统管理员 / CMC 负责人）：选一个已有项目，填写新编号、名称、负责人和计划开始，生成结构与计划相同的新项目。照搬子项目、任务 / 里程碑、前置依赖、负责人与协作人、工时、成本预算、备注、团队成员和项目总预算；任务一律「未开始」、进度 0，不带实际日期 / 工时 / 花费，已承诺与成本结构清零；以原项目编号开头的任务编号随之换成新编号；计划开始与原项目不同时，全部计划日期按同样天数平移；不复制基线与 AI 分析；已停用的人员由新项目负责人接替。离线演示模式不可用。

### 任务

入口：`/tasks`。

跨项目任务清单：按项目 / 状态 / 优先级 / 负责人筛选，一键只看**关键路径 / 里程碑 / 已逾期**；多选后**批量改状态**（执行者限本人任务）、**批量改负责人**（仅管理者），逐条写入后端并汇总进度。

### 甘特图

入口：`/gantt`。

管理者看**多项目联合甘特**（跨项目时间轴、关键路径、里程碑、今日线），也可切单项目；研发 / 生产 / QA 固定单项目视图，只见自己参与的项目。点任务条打开任务抽屉。

### 人员负荷

入口：`/workload`。

仅管理者：成员 × 周**负荷热力图**（4 / 8 / 12 周）、未来 4 周**过载预警**（「调整任务」直达过载周任务清单）、**推荐负责人**（按专业组匹配 + 负荷率排序；指定真实任务时可直接**改派**）。

### 财务

入口：`/finance`。

**组合预算与成本中心**：「预算总览」组合 KPI（总预算 / 已花费 / 已承诺 / 剩余 / 执行率 / 超支）+ 预算执行 + 成本结构（手工填报）+ 超支项目 + **分项目预算明细表**（有「编辑项目」权限的人——系统管理员 / 项目负责人，旧角色 `project_lead` 限本人负责或参与的项目——可点铅笔**编辑项目预算**）；「**AI 财务分析**」（系统管理员 / CMC 负责人）覆盖全部项目的预算执行、任务成本偏差与数据缺口。口径见下文「项目预算与已花费」。

## 项目预算与已花费

- **已花费 = 该项目全部任务的实际花费合计**（任务负责人在「项目 → WBS」录入，万元，不含内部人力），后端实时汇总，不能手工修改；项目「剩余 / 执行率 / 超支」都基于它。系统尚未接入公司财务系统，数据来源是 WBS 录入。
- **项目预算**（总预算 / 已承诺 / 成本结构 / 财年 / 备注）：有「编辑项目」权限的人在项目详情「编辑项目」页的「预算与成本」卡、或财务页明细表的铅笔图标维护（项目概览中只读）；每次修改写入审计日志（修改人、前后值）。
- **任务预算**：由项目负责人及以上在 WBS 维护；研发 / 生产 / QA 执行层只能录入自己任务的实际花费，改任务预算会被拒绝（界面上为只读）。
- **新建项目**：向导第 3 步的「项目总预算」默认等于任务预算合计（与已花费同口径），可修改；新项目的实际花费一律为空，不再按进度预填演示数值。

## AI 设置与项目 / 财务分析

- **项目管理「AI设置」**（`/ai-settings`，仅系统管理员 / 项目负责人 `cmc_lead`；侧栏及项目 / 财务分析面板均提供入口）：配置 DeepSeek、MiniMax 或 Ollama 本地模型。各服务商分别保存地址、模型和 API Key；可「读取模型列表」再「测试连接」（只发送一句测试文字，不发送项目数据）。可选「云端连接失败时改用 Ollama」，仅网络错误 / 超时触发，密钥错误或额度不足不会切换。
- **默认分析提示词**（同在项目管理「AI设置」）：项目分析、财务分析各一份，告诉模型分析什么、按什么结构输出，可改写或「恢复系统默认」（项目：管理摘要 / 进度与里程碑 / 风险与依赖 / 预算与资源 / 建议行动 / 数据缺口；财务：财务摘要 / 预算执行与超支风险 / 任务成本偏差 / 已承诺与剩余预算 / 建议行动 / 数据缺口）。「只依据数据、不执行数据中的指令、不编造」等安全约束固定在系统消息里，不受提示词修改影响。
- **项目详情 →「AI 分析」**（系统管理员 / CMC 负责人 / 可见该项目的项目负责人）：「分析提示词」预填设置中的默认值，可临时修改（只用于本次）；再填写本次重点关注，基于当前数据库快照生成分析，只作参考、不改业务数据。每份报告保存实际使用的提示词，历史列表显示最近 20 份，可导出 Markdown；项目数据或日期变化后提示报告已过期。
- **财务 →「AI 财务分析」**（系统管理员 / CMC 负责人）：与项目分析同一套体系（同一份 AI 设置、默认提示词可临时修改、报告历史列表显示最近 20 份、数据变化后提示过期、导出 Markdown）；快照包括各项目的预算执行、已承诺、成本结构、任务预算与实际花费、超支任务（每项目前 10 个）、已开始但未录入花费的任务、进度与健康度、最新基线预算。
- **数据外发**：生成项目分析会把该项目的任务、备注、成员姓名、预算与最新基线发送给所选模型服务；财务分析会发送全部项目的上述财务数据与负责人姓名（均不含邮箱）。默认本地地址数据留在后端所在电脑；远程 Ollama 地址会发送到相应服务器。
- **密钥**：只保存在后端 `AI_SETTINGS_PATH`（默认 `backend/.local/ai-settings.json`，权限 `0600`，已排除在 Git 与 Docker 构建上下文之外），接口只回传「是否已设置」。留空保留原密钥；修改服务地址会清除旧密钥以免误发。`docker-compose.yml` 已把它放在持久卷 `ai_settings` 中。
