# 自动问答与联网搜索

个人 AI 助手和研究报告中的 AI 研究助手共用自动问答流程。应用支持 DeepSeek 和 Kimi 官方搜索，随当前选中模型切换搜索服务，并复用该模型已有官方密钥；Tavily 保留为管理员显式选择的另一种适配。本节描述代码行为，生产版本与真实验收以[部署交接](部署交接简明.md)及发布回执为准。

## 用户如何使用

默认选择「自动」，正常输入问题即可：一般概念使用通用回答，需要近期信息的问题进入联网检索，明确要求依据知识库的问题进入授权知识库查询。个人助手提供自动、通用回答及联网检索，应用范围统一通过数据设置选择；研究报告另支持「仅知识库」以及指定资料范围。

明确指定的资料和范围优先于自动判断。系统沿用知识库实时权限；个人助手未允许的知识库、他人的私有资料不会因自动模式获得访问权。研究报告中已选资料仍是明确的检索范围。

个人助手的数据设置分别提供项目管理和知识库，显示当前可查询范围；不勾选也可通用问答，但不会主动查询应用数据。单选只允许读取该应用，两项都选则按问题需要读取相关应用，不强制每题同时读取。这与联网开关不同：Auto 即使没有应用数据，也可能需要公开搜索；未配置搜索时如实提示，不会静默改成最新结论。用户本轮主动附带的参考正文与应用授权分开：问题明确要求分析该正文时，使用通用分析路径，不要求启用知识库，也不把该正文发送给搜索服务；明确的知识库或项目系统请求仍需相应授权。

项目管理接入仅返回有界的项目概况，沿用实时 IAM 身份、已有有效 PM 账号及项目行级可见范围。不会因勾选创建 PM 成员、扩大项目范围或恢复任务项目归类；仅选项目管理不要求知识库连接。实际应用数据回答标为「应用数据回答」，说明使用来源，避免将项目结果标成知识库回答。

“目前有哪些任务是过期的？”等内部任务查询归入项目管理。未勾选该数据源时提示启用项目管理，问题留在助手内。当前只提供项目概况，具体任务明细及逾期清单在项目管理中查看。

研究报告重新登录恢复工作现场时，同时恢复已选择的回答方式；资料权限仍逐项重新核对，不自动扩大范围或重新发送模型请求。

联网回答的来源卡片提供「导入知识源」，确认后按应用归入「个人AI助手参考论文」或「研究报告参考论文」。只导入本人已保存回答中的公开来源；下载公开 PDF 及知识库归档由具备相应权限的账号明确发起，完整流程见[参考论文导入](reference-paper-import.md)。

每轮回答显示实际使用方式及依据。联网来源显示标题、链接、检索时间和可获得的发布日期；来源未提供日期时明确标记，不推测日期。知识库检索命中数只表示本次引用数量，不表示整个知识库的大小或全部可访问资料。

## 预览和真实状态

本地 `?preview=1` 仅演示流程和来源卡片，不调用真实模型、知识库或搜索服务。每条模拟联网回答需明确显示「界面演示 · 未实际联网」；示例不代表已经检索到某个问题的最新学术结论。

正式接口在搜索未配置时如实提示，保留问题，不把未联网的模型回答包装成最新检索结果。没有可用搜索结果、搜索服务故障、模型超时和输出超限分别处理。搜索能力状态读取失败不应阻止普通通用问答。

个人助手在联网预检失败时提供“改用通用回答”。点击后保留原问题，用户可按需再次发送。组织联网开关由管理员在服务端管理，AI 模型设置用于选择模型和配置凭据。

## 管理员配置

默认使用 `model` 跟随所选模型，管理员通过以下后端变量启用：

```env
ASSISTANT_WEB_ENABLED=true
ASSISTANT_WEB_PROVIDER=model
ASSISTANT_WEB_MAX_RESULTS=5
```

搜索复用当前选中模型的官方账户密钥，无需再填写 Tavily 密钥。DeepSeek 使用 `deepseek` 服务商及 HTTPS `api.deepseek.com`；Kimi 使用 `kimi` 服务商及 HTTPS `api.moonshot.cn` 或 `api.moonshot.ai`，保留原账号区域。地址只接受根路径或 `/v1`，并须已保存密钥。已有 `ASSISTANT_WEB_PROVIDER=deepseek` 兼容为跟随模型，无需为了切换 Kimi 更换部署变量。企业默认只读取企业模型，个人选择只读取本人该项配置；缺少、删除或第三方转发模型不借用其他模型或其他人的密钥，也不把第三方或不同厂商密钥转发到官方接口。尚未接入的模型会说明当前模型不支持，不提示用户必须使用某一家厂商。

[DeepSeek Search API](https://api-docs.deepseek.com/guides/search/) 使用固定 `/v1/tools/search` 地址，返回来源标题、链接、日期和可获得的正文/摘要。没有全文时仅依据返回片段作答，不宣称已经阅读全文；搜索没有结果、余额不足、认证失败、限流或超时会分别提示。搜索请求和模型生成分别调用，不能仅凭选择了 DeepSeek 模型名就假设已经联网。

[Kimi 官方 OpenAPI](https://platform.kimi.com/docs/openapi.json)（[国际区](https://platform.kimi.ai/docs/openapi.json)）使用所选区域的 `/v1/tools/search`：请求传入 `text_query`、`limit`、`include_content` 和 15 秒服务端超时，按 `search_results` 解析正文或摘要，不使用旧 `$web_search` 机制。客户端限制连接 5 秒、读取 20 秒，并检查整体 20 秒预算、1 MB 响应及 40,000 字资料上限；无完整正文时不宣称已阅读全文。配置检查不会发起付费搜索。

页面根据当前模型刷新搜索状态，切换或保存模型后不沿用上一个模型的就绪状态。就绪表示当前配置满足调用条件，不代表已验证账户余额或服务可达；真实调用仍执行认证和错误检查。

如管理员明确需要 Tavily，设置 `ASSISTANT_WEB_PROVIDER=tavily`，同时填写服务端 `ASSISTANT_WEB_API_KEY`。此时独立使用管理员选择的 Tavily，模型切换不改变该显式部署策略；不会在搜索失败时自动借用其他厂商。变量变更须完整传入 app 与 app-direct 并重新创建容器，普通 restart 不会更新容器环境变量。生产必须沿用完整运行覆盖文件，不能用仓库示例覆盖私有连接或功能开关。

搜索默认关闭，本地 `?preview=1` 永不调用搜索或模型。普通用户无需维护服务商配置，启用后保持「自动」即可，也可明确选「联网检索」。

公开搜索只发送当前问题所需的检索词，不自动把报告全文、附件、知识库正文、任务指引或密钥发送给搜索服务。已有个人模型配置、知识库连接和账号权限继续使用原有隔离方式。

## 数据与可追溯性

每轮记录请求的模式、实际使用模式、判断说明及真实联网来源。旧对话继续读取，旧记录不补造联网状态或来源。

研究报告采纳联网回答时，需要保留服务端验证的来源及原文快照，继续沿用报告引用和访问校验；来源不能仅由模型凭空生成。网页链接和日期由检索结果产生，模型引用编号需对应实际来源。

联网方式与来源元数据沿用 `014`，项目范围沿用 `015`；模型跟随搜索适配不增加数据库迁移，也不改写旧消息来源。新环境仍须按现有迁移流程升级并核对结构。旧项目任务的范围兼容限制见[助手说明](ai-assistant.md)，不能用这次搜索更新绕过历史权限。

## 检索质量与验证

知识库检索需排除「新的」「范围」「问题」等泛词造成的无关命中，同时保留有意义的中英文技术主题。当前仍为保守的词法主题校验，可能漏掉同义表达，不能替代语义相关性或人工核对。没有主题依据的正文不能仅凭标题匹配成为证据。

回归检查覆盖：普通问题、最新进展、明确只用知识库、禁止联网、已选资料约束、不同话题与追问、未配置搜索、搜索无结果/故障、非法来源链接、引用一致性、历史读取和报告采纳。日志记录耗时、阶段和错误分类，不记录问题正文、网页正文、知识库正文、完整 URL 或密钥。

真实联网验收需管理员完成搜索配置后，再使用同一问题检查检索结果与日期、引用可访问性及来源相关性。预览通过不等于已完成真实联网验收。

项目数据源的历史验证及已完成生产迁移见[应用数据范围发布记录](../deploy/parallel-test/releases/20261101-assistant-application-scope.md)。DeepSeek / Kimi 适配覆盖凭据归属、Kimi 区域隔离、严格官方端点、模型切换、来源解析与错误分类；测试名称使用短标识，避免将模拟正文写成超长 CI 节点名。真实搜索/模型验收需另记实际日期、结果与限制。
