# 项目计划工具与 AI 行动

[返回功能说明](features.md)。本页描述代码能力；生产版本和验收证据以发布回执为准。

## 项目 Excel 往返

项目详情页首「Excel 导入导出」先下载本项目工作簿，再上传修改后的 `.xlsx`。系统按中文表头识别字段，列可重排；预览列出行号、错误和字段前后值。填写原因后确认回导，全部通过才一次写入。

可更新已有任务的名称、负责人、优先级、计划及实际日期、状态、进度、工时、预算、实际花费和备注。明确填写 0 与清空可选值分别保留；负责人可用项目成员姓名或账号 ID，重名须改用 ID。任务 ID、项目身份和导出修订用于防止回错项目或覆盖新修改；冲突后应重新导出核对。

仅管理员、CMC 负责人或本人负责项目的 `project_lead` 可导出及回导。文件上限 10 MiB、10000 个任务；只接收本应用导出的项目工作簿，模板工作簿及任意第三方格式须先整理。参考表中的项目、团队与依赖不回写，不增删任务；自定义进度权重在「进度计算规则」维护。删除工作簿行不会删除任务。配置验收的里程碑不能通过回导绕过验收，已验收任务发生变化后须重新提交。

## 模板版本升级

项目详情 →「计划工具」→「模板版本升级」。选择来源及目标模板版本，核对模板节点与现有任务的对应关系，再预览并勾选字段级变更。系统只沿用已确认的映射或准确的实例化 ID，无法确认的历史项目需明确绑定，不按相似名称猜测。

在线编辑及 Excel 来源的历史版本按各自原格式读取，历史 JSON 保留原值；同一字段出现冲突值时明确提示修正，阻止含糊的同步。

可分批同步任务、计划、负责人、工时预算和依赖；未采纳差异下次仍保留，全部处理后才更新项目关联版本。没有字段差异时也可确认目标版本。新增任务从未开始进入项目；实际进度、日期、工时、费用、讨论和交付记录保留。已有执行、费用、协作记录或外部依赖的任务受删除保护；空子项目保留。新增或修改的模板外依赖需先整理，历史原有外部依赖保留。

普通成员按可见范围读取；仅管理员、CMC 负责人或本人负责项目的 `project_lead` 可确认应用。项目、模板或映射在预览后变化时拒绝旧确认，重新预览后再选择，不部分写入。

## 可解释的项目进度

项目详情 →「计划工具」→「进度计算规则」。先查看逐任务的有效权重、占比、进度贡献和子项目结果，再预览并填写原因确认。管理权限同模板升级，普通成员的任务明细仍受既有可见范围限制。

| 方式 | 计算规则 |
|---|---|
| 任务等权 | 全部任务权重为 1，包含里程碑，兼容既有规则 |
| 预计工时加权 | 普通任务取预计工时，里程碑权重为 0 |
| 自定义权重 | 使用填写值；空普通任务取 1，空里程碑取 0；明确填 0 则排除 |

进度 = `Σ(任务进度 × 有效权重) ÷ Σ有效权重`，最终四舍五入为整数；总权重为 0 时为 0%，页面同时显示分母及计算说明。子项目在自己的任务范围内按同一规则汇总。规则变更、任务保存、Excel 回导、结构调整、复制和离线计算使用相同口径；加权项目不能再手填项目或子项目的汇总进度。

既有项目升级后默认等权、自定义权重为空，结构升级不会重算历史进度。新基线 `schemaVersion: 3` 保存规则与任务权重，旧基线中没有的字段标为未保存，不补造历史。

若历史记录与当前规则重算值不同，页面分别显示两者。例如记录为 22%、按四舍五入重算为 23% 时，明确提示保存规则或后续更新任务后同步；打开页面本身不更改既有进度。

## 项目 AI 后台分析与行动

项目详情 →「AI 分析」。管理员、CMC 负责人或本人负责项目的 `project_lead` 可提交后台分析，离开页面后任务继续；返回查看排队、生成、完成、失败或取消状态。项目分析历史按正文和关注事项检索、分页读取，可选两份报告对比并导出 Markdown。具有分析权限且能看到该项目的管理者可读历史。

每份报告保留生成时快照、实际提示词、模型与来源时间；项目变化后标为旧快照。模型密钥沿原设置使用，不存入后台任务。执行前和模型返回后都按实时 IAM 有效角色及当前项目关系复核；双实例通过数据库领取任务。同一账号最多一个排队或生成任务，全局最多 16 个。进程中断超过 20 分钟会标记失败，不自动重发收费请求。取消会丢弃本次结果，已发送的模型请求可能仍在上游完成；可核对后重新生成。

报告中的结构化建议仅为草稿；旧报告或无法识别结构化建议时可手动添加。核对类型、名称、负责人、日期和采纳原因，逐条预览后确认：

- 新任务：选择现有子项目，创建未开始、进度 0 的任务，不改旧执行数据。
- 风险：写入「项目跟进」风险台账，包含负责人、期限、严重度及处理措施。
- 联动排期：选起点及锁定节点，复用项目工作日历和依赖预览，展示全部受影响任务；冲突时阻止执行。

预览绑定当前项目、建议内容和排期日历。内容或数据变化后必须重新预览；同一条建议的网络重试不会重复创建，执行记录保留报告来源、操作者、原因和结果入口。AI 不会自动改项目，也不会依据报告文字跳过团队、日期、验收或权限校验。组合财务分析继续沿原同步生成与最近 20 份报告流程，本轮后台队列只用于项目分析。

## 任务 AI 排期推演

在甘特图打开任务，展开「AI 排期推演」。例如输入「顺延 5 个工作日，保持 IND 申报里程碑不动」。先核对识别出的工作日数和锁定里程碑，再查看受影响任务及项目完工日期。遇到重名里程碑时用完整任务编号重新说明。出现依赖冲突时可调整要求后重新推演。

仅管理员、CMC 负责人及本人负责项目的 `project_lead` 可在在线模式使用。所选任务作为排期起点，组织默认模型解析输入文字。模型收到本次输入，任务记录、讨论和附件由应用管理。应用核对原句条件，在当前项目内匹配里程碑，按项目工作日历与真实依赖计算日期。当前支持顺延所选任务 1–365 个工作日，并可锁定一个指定里程碑。多个锁定节点或其他复杂约束可在「延迟推演」中手动设置。

预览通过后填写调整原因并确认。确认绑定操作人、项目、任务、日期差异、锁定节点和有效期。计划状态变化或预览过期须重新推演。确认成功会留下业务变更与回执。同一次确认已执行时，重复提交返回原结果。同一浏览器标签页重新打开任务可继续查看上次确认。任务日期核验失败时可重新读取，执行回执仍然保留。

此入口复用现有模型配置、联动排期与审计记录，无新增数据库迁移。

## 升级与回滚

维护身份执行 `python -m app.db.upgrade --schema-only`，为项目与任务增加进度规则列，创建模板映射、后台分析和行动记录表；运行身份仍只获 DML，不在应用启动时执行 DDL。迁移 023–025 是加法升级，保留历史执行与模型配置。后台 worker 默认启用，隔离测试通过 `PROJECT_AI_WORKER_ENABLED=false` 关闭；该开关不改变已保存记录。

回滚只切镜像并保留新列、表和发布后新增记录。旧镜像不理解加权规则、模板映射和后台任务；若已经使用新功能，应先暂停相关写入并制定兼容方案，避免旧版本按等权重新覆盖进度。不得用旧数据库备份覆盖现网新增数据。
