## 3. 打包上传并部署

**本地项目根目录执行**（发布包只含构建文件，不上传 `.env`、私钥、数据库或整个 `deploy/`）：

```sh
set -e
release_tag="update-$(date -u +%Y%m%dT%H%M%SZ)"
tar --exclude='__pycache__' --exclude='*.pyc' -czf "/tmp/$release_tag.tar.gz" \
  Dockerfile .dockerignore package.json package-lock.json \
  index.html vite.config.ts tailwind.config.js postcss.config.js tsconfig*.json \
  src public scripts/build-release-notes.mjs \
  docs/releases/notes.json docs/releases/style.css backend/app backend/requirements.txt
scp -i id_rsa -P 13568 "/tmp/$release_tag.tar.gz" \
  prometheus@36.154.190.9:/home/prometheus/mb-pm-v2/releases/
echo "$release_tag"            # 记下标签，下一步使用同一个值
ssh -i id_rsa -p 13568 prometheus@36.154.190.9
```

**进入服务器后执行**，将第一行替换成刚才输出的真实标签：

```sh
set -e
release_tag='填入刚才的 update-时间戳'
cd /home/prometheus/mb-pm-v2
umask 077
mkdir "releases/$release_tag"   # 已存在则停止，避免覆盖同名发布
tar -xzf "releases/$release_tag.tar.gz" -C "releases/$release_tag"
previous_image=$(docker inspect mb-pm-v2-app-1 --format '{{.Config.Image}}')
mkdir -p "private-config-backups/$release_tag"
cp .env "private-config-backups/$release_tag/app.env"
printf '%s\n' "$previous_image" > "private-config-backups/$release_tag/previous-image.txt"

# 仅前端改动：沿用当前后端和依赖，只替换静态页面（本次采用此策略）
docker build --target frontend -t "mb-pm-web:$release_tag" "releases/$release_tag"
cat > "releases/$release_tag/Dockerfile.frontend-update" <<DOCKER
FROM mb-pm-web:$release_tag AS web
FROM $previous_image
COPY --from=web /web/dist /code/static
DOCKER
docker build -f "releases/$release_tag/Dockerfile.frontend-update" \
  -t "mb-pm:$release_tag" "releases/$release_tag"

# 确认以上构建成功后，才修改镜像标签并只重建 app
sed -i "s/^PMS_IMAGE_TAG=.*/PMS_IMAGE_TAG=$release_tag/" .env
docker compose -f compose.yml -f compose.production.yml up -d --no-deps app
```

若**后端或其依赖也有改动**，将上面“仅前端改动”的两次构建替换为 `docker build -t "mb-pm:$release_tag" "releases/$release_tag"`，其余步骤相同。服务器 `.env` 的其他值、AI 配置和 Compose 配置保持现状，不用本地示例覆盖。

## 4. 验收与回滚

```sh
# 服务器执行；等待 app 显示 healthy，再检查公网
docker compose -f compose.yml -f compose.production.yml ps
docker inspect mb-pm-v2-app-1 --format '{{.State.Health.Status}}'
curl -fsS http://127.0.0.1:18082/health
curl -fsS https://pm.openlims.ai/health
curl -fsS https://pm.openlims.ai/release-notes.html >/dev/null
curl -s -o /dev/null -w '%{http_code}\n' https://pm.openlims.ai/api/v1/auth/me  # 未登录应为 401
```

浏览器刷新后检查登录、左侧「版本更新」、AI 置顶标签及本次修改的功能。若命令行遇到 403，再用浏览器确认；不要因此关闭 Cloudflare 安全设置。应用日志：`docker compose -f compose.yml -f compose.production.yml logs --tail 80 app`。

**验收失败即回滚：** 从本次备份的 `previous-image.txt` 取前一镜像标签（冒号后部分），仅将服务器 `.env` 的 `PMS_IMAGE_TAG` 改回该值，再执行同一条 `up -d --no-deps app`，复查健康状态。不要整份恢复旧 `.env`，也不要回退数据库。构建失败且尚未切换时，无须回滚。
