# 知识源：文件夹自动导入

本功能按《知识源文件夹自动导入 BRD V1.1》开发。入口为知识源顶部的“自动导入”，或资料库当前文件夹标题旁的“自动导入设置”。在当前文件夹打开时，右侧只显示保存到此处的任务。尚无任务时打开新建流程并预选当前文件夹。本说明描述本地实现；生产启用、客户目录连接及真实账号验收以另行发布记录为准。

## 日常操作

1. 打开“新建自动导入”后，在同一页选择扫描来源、要拷贝到的知识库文件夹和扫描时间。切换“我的电脑”和“服务器 / NAS”会保留已填写的目标和时间。
2. 从资料文件夹打开时继承当前分类；没有当前分类时归入真实的“待整理”文件夹。目标已删除或没有写入权限时要求重新选择，不自动改存其他目录。ICH 官网下载继续使用原有来源配置。
3. 服务器 / NAS 从管理员授权的已挂载根目录中选择，可以指定根目录内的相对路径；保存时自动检查目录，也可提前点击“检查目录”。不接受任意服务器绝对路径、网络分享网址或浏览器提交的 NAS 密码。
4. 从“我的电脑”可直接选择本机文件夹，也可输入完整路径。保存后在同一页连接电脑。使用选择器时，把连接程序存入下载目录，在所选文件夹打开终端并运行页面生成的命令。连接程序检查目录名并记录实际目录。填写完整路径时直接使用该路径。首次连接需要 Python 3.10 或以上版本，配对码十分钟有效。
5. 默认每日北京时间 08:00；也可改为每天其他时间、每周指定日期及时间、指定时区或仅手动。新建即扫描现有文件；“立即扫描”重复点击返回当前批次，不并行创建同任务。
6. 点击任务上的“自动导入设置”，在当前页面或侧面板中打开任务配置。默认仅展示扫描文件夹、保存位置、扫描时间三项摘要，点击“更改”仅展开对应一项；名称、大小和处理限额放在收起的“更多选项”。任务管理另行收起，删除任务仍需明确确认。修改目标只影响后续批次，原有资料不移动。
7. 任务列表以“扫描来源 → 保存到知识库”显示目录和目标，下方显示连接状态、扫描计划、上次结果及下次扫描。“暂停 / 恢复”“运行记录”直接显示文字。运行详情按文件显示保存原件、解析正文、归档及索引阶段，提供失败项和整批失败项重试。编辑输入不会被后台刷新覆盖，保存失败保留输入；手机页面底部保留保存入口。

连接程序仅向工作台发起出站请求，关闭网页不影响运行；电脑关机、休眠或离线时显示离线，恢复后继续一次未结束扫描，不补跑离线期间每一天。已传至服务器的文件由后台继续处理。配对授权可通过重新配对或删除任务撤销；连接程序不接收知识库签名密钥、Core token 或数据库凭据。

## 文件与版本规则

- 首期扫描 PDF，包含子文件夹默认开启；隐藏文件和符号链接跳过。子目录默认合并到同一目标，可显式开启保留层级。
- 单文件上限默认 100 MiB，可在任务中降低；服务端也可降低总上限。每批默认至多 1000 份，最高可配置 10000 份。达到数量上限会提示分批，后续扫描从上次位置继续，不能用不完整列表判断文件消失。
- 每日处理上限默认 1000 份，可设 1–50000 份，按任务配置时区的自然日统计成功完成的新增 / 更新文件。达到上限后显示“今日额度已用完，次日继续”和恢复时间；保留当前队列，次日自动继续，不重建批次、不重做完成文件，也不将任务永久暂停。调高上限可在同批次继续。未变化文件不占每日完成额度。
- 读取前检查稳定时间，读取后核对大小、修改时间及文件身份；尚在写入、无法完整读取或校验不符不标为成功。PDF 解析另有现有的 1000 页、正文 200 万字符及资源限制；加密文件和需要 OCR 的扫描件保留原件并提示原因。
- 内容 SHA-256 用于去重；文件名不同但原件相同可共享原件和已完成结果。目录不变时不重新上传、解析和建立索引。
- 同一路径内容变化保留原版本；新版索引成功后由配套知识库 / Core 的版本指针切换默认版本，旧原件保留可追溯。仅登记新版本或仅保存原件不能显示“已完成”。
- 删除源文件只记录来源缺失，不删除知识库资料。NAS 断连或扫描失败不会作为成功空目录提交；已保存资料保留。
- 用户在知识库删除的同版资料受知识库持久删除屏障保护；改名或再次扫描不会自动恢复。重新导入需要显式处理删除状态。
- 修改目标只影响后续批次，运行中批次保留启动时目标。目标被删或权限失效暂停处理并提示，不改存其他位置。暂停和删除任务允许当前阶段安全收尾；删除任务不删除已入库资料。

## 后台与权限

门户接口前缀为 `/api/v1/knowledge-sources/v3/folder-imports`。浏览器写操作使用现有门户会话、同源校验和实时管理员 / 知识库负责人角色，并由知识库再次检查写入权。本地连接程序使用独立的任务授权，只能提交本任务、当前扫描租约内的相对文件路径。

任务、扫描批次、文件结果、来源位置、配对授权、每日用量和幂等计量事件沿用 `information_entries`，正文沿用 `information_texts`；原件仍在 `INFORMATION_DATA_DIR` 内容寻址存储中。门户侧不新增数据库表或迁移；配套 Core 扩展新增两个版本元数据表，具体范围见[Core 扩展](../extensions/knowledge-folder-core/README.md)。连接程序令牌仅保存哈希；一次性配对码不保存明文。扫描结果和已完成阶段持久化，临时失败最多自动尝试三次，手动重试复用已保存原件和正文。

文件夹导入当前固定串行处理，并发数为 1；使用独立后台线程及数据库租约，和 ICH 采集任务分开调度；扫描及大文件读取中续约，两实例不能同时处理同一队列。日程按配置时区计算，恢复后合并过期触发。读取服务器文件时逐级使用不跟随链接的目录句柄，防止路径穿越和检查后被替换为链接。

知识库接口为 `folderImportPaper`、`indexFolderPaper`、`statusFolderPaper`，须使用[同版 Core 扩展](../extensions/knowledge-folder-core/README.md)提供目标文件索引和原子版本切换能力。索引必须由同版 Core 的目标文件能力提供，并验证该文件的注册与新版发布证明；不支持时明确失败并保留原件，不回退到全库增量或全库重建。模型摘要、翻译、OCR 及研究报告生成不由本任务自动启动。

## 配置与运行

后端示例：

```dotenv
KNOWLEDGE_SOURCE_APP_ENABLED=true
KNOWLEDGE_SOURCE_WORKER_ENABLED=true
KNOWLEDGE_FOLDER_IMPORT_ROOTS=[{"id":"papers","name":"研究资料挂载","path":"/mnt/research-papers"}]
KNOWLEDGE_FOLDER_IMPORT_MAX_FILE_MB=100
```

根目录应由运维只读挂载到实际工作进程可见的位置，两个运行实例须采用一致的授权目录和文件夹配置；不在前端填写 SMB / NFS 凭据。服务器目录不可达或挂载设备变化会暂停并要求核对。原件空间仍受 `INFORMATION_MAX_ARCHIVE_MB` 约束，应保留原件持久卷和备份。

本地连接程序需 Python 3.10+，不额外安装依赖。在页面生成配对码后执行：

```sh
python3 scripts/knowledge-folder-connector.py --server http://localhost:1234 --code '<一次性配对码>' --folder '<已授权的本机目录>'
```

正式工作台使用 HTTPS 地址。令牌配置写入本机权限受限的状态文件；不要上传状态文件或把它加入代码仓库。常驻与开机启动选项以 `--help` 为准；电脑离线时无法扫描本机尚未上传的文件。

每日用量按任务时区持久保存：完成文件数、新内容原件归档字节、成功解析页数及字符数、索引完成确认数、内容复用件数。计量事件和阶段结果在同一事务提交，重试及无变化扫描不重复计量，复用正文不重新累计解析量；历史用量可从任务用量接口读取最近 31 个日记录。“索引完成确认数”不是 embedding Token 或实际账单，不能据此编造金额。扫描没有自动启用 OCR、摘要或翻译；当前已接入每日完成量、单次批量、单文件和原件磁盘容量限制。

## 验证

首次验收使用 **10 份内容不同且可解析的 PDF**，验证全部保存、归档、解析和索引可检索；10 是验收样本量，不是产品扫描上限。相同目录再次扫描应新增为 0，不重复建立索引。

在 `backend` 执行：

```sh
PYTHONPATH=. python -m pytest -q tests/test_folder_imports.py tests/test_folder_import_api.py tests/test_worker_isolation.py
```

这些自动测试使用隔离数据库、真实 PDF 字节和解析进程、受控 IAM / 知识库响应，覆盖十份首扫、更新、去重、部分失败、路径边界、令牌撤销、断点续传、暂停 / 删除 / 目标切换竞态、时区、午夜恢复、调高配额继续和用量幂等。

2026-11-17 的隔离跨服务验收已运行真实门户处理流程、PDF 解析子进程、HMAC 知识库 BFF 与 Core SQLite：首次 10 份不同 PDF 全部完成原件保存、解析和目标索引；重扫为 10 份未变化；第二任务引用相同 10 份时没有额外向量生成。本地连接程序另经过真实 HTTP 配对、清单、1 份新增 multipart 上传和 9 份内容复用，全部 10 份完成，新增本机文档由真实 `/v1/retrieve` 检索命中。该联调覆盖包含每日配额的版本。

验收入口为 `scripts/verify-folder-import-stack.py`，证据保存在工作区 `local-development/2026-11-17-folder-auto-import/verification/full-stack.json`。测试使用临时目录与隔离数据，IAM 身份和向量供应商为明确的测试替身，不调用付费供应商；Core 的分块、SQLite 存储、任务回执和检索是真实执行。它不能代替实际 NAS 挂载、Windows 客户端、PostgreSQL、长时间离线或真实模型质量验收。现有本地数据库、模型配置与生产数据未被该验收替换，本轮仍未部署客户系统。

Core 扩展要求固定兼容版本及单 Core 写入进程，不能由未扩展 Core 或其他进程并行写同一个库；启动、两张版本元数据表与 PostgreSQL 待验边界见[Core 扩展说明](../extensions/knowledge-folder-core/README.md)。
