# 备份查看与删除管理

[返回功能说明](features.md) · [配置说明](configuration.md) · [主机适配器](../deploy/data-backup/README.md)

本版按「知道计划、每次备份什么、占用多少空间、能选择删除」提供管理功能。工作台业务管理下方为数据管理，进入数据备份。现有备份脚本及cron继续运行，应用不新增调度、创建备份、修改原数据或恢复生产数据库。

## 页面与数据来源

| 内容 | 来源和口径 |
| --- | --- |
| 备份计划 | 宿主机实际启用的已知cron及明确时区；无法确认或多份任务冲突时明确提示，不展示新代理默认计划 |
| 保留规则 | 当前执行脚本的可核对规则；未识别脚本显示待确认 |
| 每份备份 | 纳管目录中的真实普通归档文件，包含时间、文件大小、实际磁盘占用和来源分类 |
| 每份内容 | 历史归档认证、清单与摘要核对后生成业务名称；旧文件无可信清单时显示待确认，不按现有配置推断 |
| 目录和总占用 | 对明确纳管的备份根目录统计，区分可管理归档与其他只读备份材料；共享硬链接避免当作独立副本 |
| 删除记录 | 服务端记录操作者、时间、数量、容量和最终结果；部分失败如实显示 |

列表不展示账号口令、连接字符串、原始配置、数据库记录或论文正文。系统管理员能看到公司备份记录；其他成员没有备份API权限。

## 选择删除

管理员可选择一份或多份备份，预览文件名、数量和容量，输入界面要求的确认文字后提交。预览令牌短期有效，绑定当前操作者及当时文件身份。文件已被替换、计划任务/发布占用锁、选择过期或账号改变时必须重新加载，不按旧页面静默删除。

删除只作用于指定纳管目录中的归档普通文件，不删除业务数据库、数据卷、文件夹或不认识的材料。最后一份已验证的完整可恢复备份受保护；尚未建立至少一份完整备份核对记录时不能开始删除。保护原因会在界面显示。删除不可撤销，成功及失败均写入私有审计；重复提交同一请求不重复执行。

本版自动保留由生产原脚本负责。页面的明确人工删除是独立操作，仍受最后副本和使用中保护。不会借更新界面改变客户既有保留计划。

## 部署与验收

在最新main上提交PR，全部CI通过后squash合并，固定合并提交构建。安装同版本的宿主适配器、私有配置和HMAC密钥，以仅后端可访问的私有地址提供服务；不得暴露公网路由。宿主入站受限时可使用私有Unix套接字与Docker私网中转；中转没有备份文件、解密密钥或Docker权限，原防火墙不变。后端配置 `DATA_BACKUP_AGENT_URL` 与 `DATA_BACKUP_AGENT_SECRET`。不挂载Docker socket，不改现有backup cron及脚本。

上线前核对纳管根目录不重叠、真实文件权限、原cron与业务时区，保持旧备份与业务数据。历史归档初次扫描需要时间，扫描未完成时如实显示。先使用独立合成目录验证选择删除、最后副本保护、锁冲突及文件变化，再通过真实只读目录验收计划与容量。不要为了验收删除客户现有备份。

生产应用发布仅重建两个PM实例，完整保留其会话密钥、知识库连接、已有覆盖配置、安全设置、挂载和数据库结构；失败用固定旧镜像与原配置回滚。主机适配器停用不影响现有备份计划。

本版不提供异机备份或网页恢复。它管理已经存在的备份副本，不能替代独立存储和恢复演练。
