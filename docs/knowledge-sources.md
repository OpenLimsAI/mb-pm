# 知识源

知识源是知识库论文与文件夹管理器，入口 `/knowledge-sources`。它读取既有知识库论文及文件夹，按需从 ICH 下载公开 PDF 并归入来源文件夹。旧行业信息应用、旧管理接口和自动监控保持下线。

## 论文与文件夹

- 首页直接显示已有知识库论文，不用 ICH 目录中尚未下载的条目充当已保存论文。目录清单直接显示在来源页，不与已保存论文混在一起。
- 同一论文可属于多个文件夹，修改的是分类关系，不复制或移动 Core 原件。支持新建、重命名、批量放入、从当前文件夹移动和移除；从文件夹移除不删除论文。
- Core 论文没有可确认的 PDF 原件时只提供原有知识库阅读入口，不宣称原件已下载或问答索引已完成。
- 已下载但尚未进入 Core 的 PDF 仍可阅读和分类。归档与知识库索引分开显示；解析、索引失败不删除原件。
- 已链接 Core 的论文被删除或不再可读后，不通过 PM 历史归档重新展示。新原文入口也实时核对关联 Core 论文可见性。
- 收藏按已验证发行方、组织和个人身份持久化，不改变团队文件夹。

首页文件夹管理面板包含全部主题和来源文件夹，支持搜索、类型筛选、清晰数量、空文件夹说明和独立重命名。勾选论文后可直接在目标卡片“放入此文件夹”，保留已有分类；移动仍是当前文件夹内的明确操作。首页“从来源下载”为突出主操作。

## 来源与下载

1. 在论文搜索源添加 HTTPS 官方网址和名称。ICH 复用原有来源，默认四类 Q/S/E/M；其他来源仅登记待适配，不执行通用网页抓取。
2. 默认接收文件夹使用来源同名文件夹；ICH 创建或复用 `ICH`。用户可明确指定现有文件夹。
3. 点击“再次搜索”，由后台逐类检查目录。结果直接更新到来源设置下方，不弹出预览窗口；搜索本身不下载 PDF。
4. 在页面内按标题、分类、下载状态或 NEW 筛选；每页 25 份。“全选本页”只作用于本页；选择 Q/S/E/M 分类后，“全选本类”跨全部分页选中当前分类、关键词和下载状态下的文件，默认只选择未下载资料。切换分类会保留先前选择，共享资料不重复选择；可用“清空选择”重置。选择是否建立问答索引后，点击“下载所选”才创建任务，提交后保留当前页面。
5. 后台逐份保存原文、提取正文并按选择提交知识库索引。离开页面不影响任务，运行记录保留逐项结果；可暂停、继续或仅重试失败项。
6. 完成后打开目标文件夹整理；同内容复用既有原件和知识库入库回执。旧文件夹分类不会因重新下载而被覆盖。

NEW 表示最近一次成功搜索首次发现的逻辑文档。首次范围搜索建立存量基线，不把全部旧资料标 NEW；下次对应范围成功搜索会刷新标记，失败和未搜索范围保留原标记。既有文档 URL 或官方状态变化不冒充新论文。新增标记由服务端持久化，刷新页面不会伪造新增；只表示新发现，不表示未读、已保存或可问答。

同来源存在排队、运行或暂停任务时，清单仍可查看、筛选和预选，但不能重复启动搜索或提交下载；通过“查看当前任务”继续处理。

原文继续使用 `INFORMATION_DATA_DIR` 的受保护共享卷及 SHA256 内容寻址。大小、配额、公开 ICH 路径、robots、超时、速率、原文保护和扫描件限制沿用原实现，见[历史说明](information.md)。采集不调用生成式云端模型；选择知识库索引时使用已有嵌入配置。

## 身份与权限

所有 `/api/v1/knowledge-sources/*` 使用现有门户会话、强制改密和实时 IAM 身份。写入校验本站 Origin，不接收演示身份或浏览器 Core 令牌。

- 阅读完整 Core 文献库：实时 `kb_manager`、`kb_editor` 或 `kb_viewer`，由知识库桥接独立判断。
- 文件夹整理：实时 `kb_manager`，同时校验实际活跃论文、租户、版本及分类 revision。过期 revision 返回 409，前端刷新后重试。
- 来源配置与下载：沿用 `admin` 或 `kb_manager` 的公开 ICH 收录委托。单有 `admin` 不意味着获得全库阅读、通用上传、删除或模型设置权限。
- 对尚未链接 Core 的官方归档，保留原组织内的已验证阅读边界；归档分类待知识库创建后同步到同一份论文。

知识库不可连接或角色不允许时，界面显示实际连接问题，不加载示例论文替代真实结果。旧 `/information` 页面不因新应用上线而恢复。

## 配置和后台执行

| 配置 | 默认值 | 行为 |
|---|---|---|
| `KNOWLEDGE_SOURCE_APP_ENABLED` | `true` | 新应用和接口总开关 |
| `KNOWLEDGE_SOURCE_WORKER_ENABLED` | `false` | 手动下载后台；生产启用时须显式设 `true` |
| `INFORMATION_APP_ENABLED` | `false` | 旧行业信息保持下线 |
| `INFORMATION_KB_URL` / `INFORMATION_KB_SECRET` | 既有值 | 复用内网 HMAC 知识库桥接，不更换 Core 凭据 |

新线程 `knowledge-source-collector` 只执行带 `app=knowledge-sources` 标识的手动任务，使用原数据库 lease 协调两个 PM 实例；不扫描旧来源定时计划，不运行、恢复或改写旧采集队列。即使遗留来源仍保存 `enabled=true`，新后台也不会自动执行监控。部署本身不会下载全量 ICH 或启动索引。

API 包括 `snapshot`、`folders`、`papers/folders`、`stars`、`sources`、`sources/{id}/check`、`jobs`、`jobs/{id}/control`、`documents/{id}/retry` 和受保护原文。知识库服务新增签名 `library` 与 `folderMutation` 操作，保留原有收录/状态协议；需先发布兼容的 KB 服务再启用新 PM。

## 验证与交付边界

单元与 HTTP 回归使用隔离数据库、显式测试身份和可控 Core/ICH 响应，验证论文去重、文件夹多关联、归档原件、个人收藏、同源权限、删除屏障、任务暂停竞态和旧队列隔离。生产切换应额外记录固定源码、两个 PM 与 KB 镜像、数据库/分类/原件备份、只读核对及回滚目标；真实线上状态以发布回执为准。

## 界面规范

知识源沿用研究报告和我的笔记的深蓝应用顶栏、青蓝主操作、浅灰工作区与白色面板，统一字体、按钮、输入框、侧栏、卡片和弹窗间距。顶部复用 `ApplicationActions`，提供应用工作台、当前账号设置及共享主题切换。论文列表、来源设置和下载任务使用同一套样式；私有类名使用 `kso-*` 并限定在知识源容器内，避免研究报告懒加载后的 `.ks-*` 样式留存污染。门户知识区按研究报告、我的笔记、知识库、知识源排列。
