# 研究报告撰写工作台

[返回功能说明](features.md) · [原有应用与模型配置](knowledge-solutions.md) · [本地开发](development.md#研究报告工作台验证)

本文描述 2026-11-02 本轮代码实现，发布和目标环境验收状态以发布回执为准。应用入口为 `/solutions`，从工作台进入时先显示报告主页。已移除的「报告资料」页签、资料弹出窗口按钮与提交评审入口不恢复。

## 使用方式

| 功能 | 操作与结果 |
|---|---|
| 富文本撰写 | 工具栏设置标题、粗体、斜体、列表、引用、表格和图片；正文仍以 Markdown 保存，支持撤销与重做。 |
| AI 内容采纳 | 每条回答可插入报告，选择章节及章末、光标处、选区后或替换选区；替换前核对原文和结果，原文已变化时重新选择。 |
| 原文引用 | 在知识库阅读区选择实际文字后引用到章节，保留资料标题、版本、原文选段和来源入口。 |
| 版本恢复 | 保存时自动保留阶段快照，也可创建命名快照、比较章节文本并只恢复指定章节。 |
| 问答范围 | 查看并逐项移除当前选用资料，明确下一轮问题会查询哪些资料。 |
| 对话管理 | 按主题搜索、重命名、归档或删除对话；停止等待当前回答，已采纳的报告内容保留。 |
| 章节与模板 | 拖动排序，调整父子层级，复制章节；将章节结构保存为个人模板，供新报告使用。 |
| 复用笔记 | 搜索当前账号的「我的笔记」，选取已有记录并插入正文，保留返回笔记的链接。 |
| 导入与导出 | 导入 Word、PDF、Markdown，预览整份报告，导出 Word、PDF 或 Markdown。 |
| 报告整理 | 主页支持卡片与列表、标题搜索、项目和标签筛选、置顶及更新时间排序。 |

分栏、模块尺寸和专注模式继续沿用系统样式。章节目录可收起，辅助面板按需展开；这些显示偏好留在浏览器，不参与报告版本更新。

正文工具栏以按钮组切换「可视编辑 / Markdown」。可视编辑区域随正文增长，末段填满可用纸面；插入行内问答后，中间段落按内容收紧。正文聚焦以工具栏下沿提示，空章节显示撰写提示，避免粗外框和无法点击的底部空白。

正常返回报告时静默恢复章节及研究位置；只有恢复未发送问题、未保存正文或中断提问时提示。未发送问题提示 5 秒后消失，草稿仍保留。联网回答的来源卡片可导入知识源「研究报告参考论文」，再按权限下载公开原文；侧栏、行内与选中文字问答均提供入口，见[参考论文导入](reference-paper-import.md)。

## 正文、引用与 AI

编辑器支持粘贴经过清理的 HTML，并转为 Markdown；脚本及不支持的样式不会作为可执行内容保存。行内 `/` 问答卡片仍是临时编辑状态，明确采纳后才写入报告；未采纳的卡片位置不跨刷新保存。

知识库引用须来自当前账号有权阅读的资料。报告后端重新读取原文并校验版本、标题、定位信息和选段，不信任浏览器传入的引用对象。Markdown 渲染后的可见选段会按显示规则归一化后比对原文，不要求是正文开头；不能自行添加不存在的页码或实验结论。新增引用时来源版本变化，或已有资料撤权时，保留报告草稿并提示处理。已采纳的历史选段保持原版本，保存及恢复时重新检查来源访问权限，不因原文更新而自动改写。

AI 回答不会自动写入正文。插入和替换前检查报告、章节、修订号及选区是否仍有效，失败时保留未采纳内容。停止生成会中止客户端等待，并在服务端提交答案前检查连接是否已断开；已经发送到模型供应商的请求可能仍执行或计费。归档主题不能继续提问，删除主题的迟到回答不能重新写回历史；删除主题不删除先前已插入报告的内容和引用。

笔记复用读取统一服务端笔记，不依赖论文知识库的浏览器缓存。插入的是当时的正文副本与 `/notes?note=...` 来源链接；笔记后续修改不自动改写报告。来源链接仍要求原笔记所属账号登录，已移至回收站或无权读取时不显示正文。个人笔记不会伪装成经过知识库原文校验的论文引用。

## 保存、章节与历史

报告内容、置顶、标签、个人模板和对话主题保存在服务端，按 IAM `issuer + owner_id` 隔离。报告及主题修改分别带修订号，旧版本写入返回 `409`，不能静默覆盖其他标签页的修改。

自动快照保存修改前的报告，以五分钟为间隔节流，避免每次自动保存都产生版本；首次实质修改会留下原稿。仅修改置顶或标签不创建正文快照。命名快照保存当前已保存内容并递增修订号。单章恢复保留其他章节，恢复该章的引用并重新校验来源权限；如果历史父章节不存在则恢复到顶层，不能产生循环或超出层级限制。已有整份版本恢复与历史数据继续兼容。

章节最多 60 个，父子层级最多 6 层；拖动不能放进自己的子章节。个人模板只保存标题和层级，不复制正文、引用或他人的资料，每个账号最多 100 个。正文去除内嵌图片数据后，每章最多 5 万字符、整份报告最多 20 万字符；含图片的保存内容每章最多 400 万字符、整份最多 1,200 万字符。

## 导入、预览和导出边界

导入单文件上限 20 MB，接受 `.docx`、`.pdf`、`.md`、`.markdown`。先预览并确认名称，再新建报告；不会覆盖正在编辑的原稿。Word 导入保留可识别的标题、段落格式、列表、表格及受支持的内嵌图片，Markdown 导入按标题组织章节，长正文会在限制内分章。旧 `.doc` 应先另存为 `.docx`。PDF 导入提取文本，不提供 OCR，也不保证还原复杂版式、图片和多栏表格。

图片使用内嵌数据，不在预览或导出时下载远端图片。上传图片单张不超过 1 MB；正文存储校验 PNG、JPEG、WebP 的声明和文件标记。Word 导出可嵌入 PNG、JPEG；无法支持的图片保留文字提示。Word 导入还限制压缩包条目与展开体积，避免异常压缩包耗尽内存。

Word 导出生成可编辑的段落、标题、列表、表格、图片及参考依据，并包含目录域与页码域。目录页码需要 Word 等支持域的编辑器更新。PDF 在浏览器按页面排版后生成下载文件，保留可见格式和中文，当前采用页面图像，不承诺文字可选中、全文检索或无障碍文本层。Markdown 导出保留正文标记和参考依据。

整份预览与导出只使用已采纳的报告内容；大表格、长段落和复杂导入文档仍应在导出前检查分页。兼容旧报告的配方数据仍保留在服务端和 Word 导出中，撰写界面不重新提供配方表编辑器。

## 接口与迁移

所有路径均位于 `/api/v1`，复用门户身份和写操作同源检查。

| 接口 | 用途 |
|---|---|
| `GET/POST /solutions/templates`、`DELETE /solutions/templates/{id}` | 当前账号的结构模板 |
| `POST /solutions/{id}/versions` | 按当前 `revision` 创建命名快照 |
| `POST /solutions/{id}/versions/{version_id}/restore-section` | 按当前 `revision` 恢复指定 `section_id` |
| `GET /solutions/{id}/topics` | 主题元数据，兼容原有回答历史 |
| `PUT/DELETE /solutions/{id}/topics/{topic_id}` | 修订号保护的重命名、归档或逻辑删除 |
| `GET /notes/{id}` | 当前账号未删除的笔记来源 |

迁移 `019_report_workbench` 在 `018` 后添加报告 `pinned`、`tags` 与 `solution_templates`、`solution_topics` 表；旧报告默认不置顶、标签为空。章节层级在既有 JSON 中保存，无父级的旧章节视为顶层。自动快照复用既有版本表。本轮 Word 导出使用标准库 OOXML 打包，未增加 Python 运行依赖；富文本与 PDF 导出新增的前端依赖由锁文件固定。

生产应用以受限数据库角色运行，`AUTO_MIGRATE_SCHEMA=false`。已有标准 Alembic 台账的环境可沿对应分支迁移；现网属于历史 metadata 初始化，部署助手先核对 017 所需结构、018 全部已验证业务约束与现存数据，再由独立维护身份定向执行固定 019 文件，首次建立 019 台账。已有台账的环境只追加记录，不重写原行；重复执行必须幂等。迁移后验证运行角色对新增表具备 DML 权限。不要在已有业务表但无台账的库中补跑整条旧迁移链，不要让应用容器自行建表，也不要以恢复备份代替镜像回滚。既有 MDM `007` 为另一条迁移分支，本次不改变该链。
