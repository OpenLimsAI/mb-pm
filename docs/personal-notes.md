# 我的笔记

独立「我的笔记」和知识库中的「我的笔记」共用门户服务端的 `personal_notes` 数据，按已登录账号的 issuer + subject 隔离。知识库摘录、问答回答以及研究报告、行业信息中的笔记都可在同一界面查看、编辑、搜索、删除和恢复。两个页面聚焦时刷新，打开期间每 15 秒读取更新；编辑冲突返回 409，保留当前草稿供核对。

来源分类统一按「研究报告 → 知识库 → 行业信息 → 个人记录」排列；独立应用侧栏、窄屏分类和嵌入式来源筛选使用同一顺序。

## 阅读与编辑

独立「我的笔记」和知识库内嵌笔记采用三栏：左侧按来源分类，中间单列显示笔记标题、正文摘要、来源和更新时间，右侧显示所选笔记的完整正文。点击列表直接切换阅读，不弹出编辑窗口；新建和编辑在右侧面板完成。正文支持 Markdown 阅读，列表摘要隐藏 Markdown 标记。

正文默认以文档方式可视编辑，复用研究报告的编辑基础：直接输入内容或选中文字，使用工具栏设置标题、加粗、斜体、删除线、项目列表、编号列表、引用段落和链接，并插入、修改表格或图片。撤销 / 重做保留当前编辑过程，也可使用对应键盘快捷键。需要编辑源文本时可切换「Markdown」，再切回可视编辑；原有 Markdown 内容打开后不会仅因进入编辑器而自动保存或改写。

正文仍以 Markdown 保存，上限为序列化后的 50,000 字符，格式标记与内嵌图片数据也计入容量；容量不足时保留当前草稿并提示缩短正文或调整图片。可视编辑负责常用文档格式，特殊 Markdown 语法可在源文本方式中核对。正文须点击「保存笔记」才提交，不进行自动保存。

切换笔记、来源或搜索前，如有未保存内容，会在面板内提示继续编辑或放弃更改；也可先保存后继续原操作。保存过程中禁止切走，后台刷新不会覆盖编辑草稿，修订冲突保留正文。回收站内容可阅读、恢复，恢复后才可编辑。

桌面各栏独立滚动；中等宽度将来源分类收至顶部，窄屏在笔记列表与正文之间切换，并提供「返回笔记列表」。研究报告、知识源等阅读选区的「存入我的笔记」仍使用轻量摘录窗口，正文采用同一可视编辑器。

## 数据边界

- 正式模式不读取、导入、覆盖或删除旧浏览器笔记；本次不处理历史 Wisdom 副本。
- 新摘录直接调用服务端接口，失败时保留当前摘录/回答，重试沿用同一 ID；没有「自动保存到浏览器后稍后迁移」的回退。
- 知识库嵌入同一笔记界面，以当前知识库身份摘要绑定门户会话。跨域请求仅允许配置的知识库 Origin，且必须与门户会话的 issuer、subject 一致。
- 独立笔记、研究报告、行业信息和知识源摘录的笔记请求固定绑定打开页面时由门户验证的身份摘要。其他标签页切换账号后，尚未刷新身份的旧页面读写请求会被拒绝，并保留打开的正文供复制；同一编辑器的客户端身份变化也会暂停保存，不能自动转存到新账号。真正刷新到另一账号时，现有账号隔离边界会卸载原账号页面和未保存草稿；本次不新增跨账号草稿恢复。笔记 API 不再接受只有会话 Cookie、缺少预期身份的读写请求；缓存旧前端的页面须先复制未保存正文，再刷新确认账号。知识库原有身份头与嵌入摘要继续有效。此防护已在代码中实现，实际部署与真实账号验收状态另记。
- 嵌入页面读取同账号笔记成功后，向指定知识库 Origin 发送就绪状态；父页同时校验发送窗口和身份摘要。页面被浏览器阻止或连接超时会显示重新加载、在新页面打开入口，不再留下空白框。后续登录失效或账号不匹配会撤下嵌入内容，普通刷新失败保留正在编辑的内容。
- 两个应用须登录同一账号。退出、账号不匹配或临时密码未修改时拒绝访问，不展示其他账号数据。
- 开发预览的演示笔记仍独立保存在本机，不能作为正式数据来源。

## Wisdom 检索副本

笔记默认私有。用户显式选择「共享到知识库检索」并确认后，具有实时知识库编辑权限的账号可发布检索副本；共享后知识库成员可能在检索和 AI 问答中使用内容。撤下共享和移入回收站会安排移除检索副本，不要求用户仍有发布权限。

`note_wisdom_sync` 是持久化的合并任务表。正文版本变更与期望同步版本在一个数据库事务中保存。后台工作线程使用 PostgreSQL advisory lock，在门户与直连实例之间串行执行任务。

每个版本/尝试采用独立、带笔记 ID 的 Wisdom 路径。更新前先通过 Core delete 任务删除旧索引，再发布最新内容；不使用 `status=archived` 代替索引删除。恢复时重新发布。已接受的远端任务保留 task ID；提交响应丢失时遍历任务日志核对摘要，不盲目重复 POST。远端任务明确失败或部分嵌入失败时清理该次副本并重试。后台错误显示在笔记卡片，不影响正文保存。

无法确认远端是否接受的任务会持续核对并保持错误状态；若 Core 任务日志已被清理或任务从未创建，需要管理员核对后处理，不自动假定成功或重新提交。同步为最终一致，完成前检索可能短暂仍含上一版内容。

## 配置

- `KNOWLEDGE_NOTES_ORIGIN`：允许访问笔记 API 的精确知识库 Origin，生产默认 `https://kb.openlims.ai`；同时仅允许该 Origin 嵌入 `/notes?embed=knowledge` 的 HTML 页面。不得配置通配符、路径、凭据或多个 Origin，其余门户页面沿用原有 `frame-ancestors` 限制。
- 本地知识库挂载到 `http://localhost:1234/knowledge-base` 时，知识库 Origin 是 `http://localhost:1234`，不含路径。此时普通门户笔记继续校验门户身份摘要；知识库笔记继续校验其显式 issuer/subject，不因同源而混淆两个调用方，也不跳过写操作的精确 Origin 检查。读取、保存和重试始终绑定原账号。
- `NOTES_WISDOM_CORE_URL` / `NOTES_WISDOM_TOKEN`：后台专用 Core 地址和服务令牌，不发给浏览器。
- `NOTES_WISDOM_WORKER_ENABLED=true`：启用后台同步线程。两实例可以同时启用，共用数据库锁。生产必须使用 PostgreSQL；单进程 SQLite 仅供本地调试。

未配置检索连接时拒绝新增共享，个人笔记 CRUD 正常可用。部署前备份数据库和配置；013 仅创建任务表，无历史笔记数据回填。回滚保留数据表和新增服务端笔记，暂停新 worker。回滚到旧知识库界面将不能从该界面访问新的服务端笔记，独立笔记应用仍保留记录。
