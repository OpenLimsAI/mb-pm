# 项目 AI 助手

当前简化交互已于 2026-11-15 随固定 main `61a85ab` 与笔记统计共同发布；版本、验证范围及回退见[发布记录](../deploy/parallel-test/releases/20261115-project-ai-assistant-simple.md)。真实客户完整交互及客户资料下的模型效果仍待验收。

从侧栏「项目 AI 助手」（`/project-assistant`）进入，或在项目工作台、项目详情、任务详情展开同一助手。界面围绕当前请求组织：输入需求 → 查看结果 → 必要时核对修改。项目/任务页自动带入当前范围，按当前账号的权限读取资料。

## 直接使用

首屏提供一个输入框和「发送」，以及最多三个示例问题。发送「这个项目有哪些延期任务」「整理本周周报」等明确请求后，助手识别范围和处理方式并继续执行；只有对象重名、范围不明确或缺少必要条件时，才追问相应信息。不再要求每个问题都先点「识别范围与操作」再确认一次分析。

- 「查看待关注任务」直接读取当前范围内的任务事实，显示排序理由和原任务入口；不调用模型。
- 「整理本周周报」显式启动模型分析，结果作为当前这次请求的草稿展示。草稿可本地编辑、复制与导出，编辑不改写原始分析及建议依据。
- 「粘贴会议记录」仍使用同一个输入框。原文随这次请求传入，不要求到另一个表单重复输入；提取出的修改须预览并确认。

工作重点按阻塞、逾期或标记延期、七天内到期的里程碑/关键路径任务及其他即将到期任务排序。同档按截止日期、项目编号、任务编号和任务 ID 排序，支持限量和仅查看本人负责或协作的任务。明确查询逾期、延期或阻塞时只返回对应类型；逾期与状态标记分开判定，不把所有重点都称为延期。

任务名称保留可直接打开的原记录入口。资料时间、模型和完整依据在结果中按需展开，历史记录不与当前问题同时常驻显示。

## 请求与结果

| 需求 | 结果 |
| --- | --- |
| 工作重点、逾期/延期/阻塞任务 | 当前可见任务清单、事实理由及任务入口 |
| 异常解释 | 可见依赖、风险与变更支持的分析判断及资料缺口 |
| 项目周报 | 指定范围内的周报草稿与待决定事项 |
| 会议更新 | 原文引用及待核对的任务、风险、问题或决策草稿 |
| 措施跟踪 | 已处理、仍阻塞与尚缺结果证据的事项 |
| 排期比较 | 最多三个顺延工作日方案、固定节点冲突及日期/负荷影响 |

普通查询和生成报告都由用户发送需求触发；打开助手、切换范围和查看历史不自动生成模型报告。生成在后台处理，离开面板不取消；新分步运行可以暂停，旧运行可以停止。新问题进入新的当前请求，不混入上一份完整结果，也不隐式取消已提交的后台任务。

排期仍使用真实项目日历、依赖与固定节点。建议改动以差异预览展示，确认后才执行。任务抽屉内旧「智能排期」及其深链接继续可用，保留原权限、回执和未保存进展保护。如果上次已确认的调整尚未取得回执，发送新排期要求会明确提示本次尚未预览；「重试上次确认」只恢复原方案，取得回执后可开始新推演或新比较。

## 分步整理与继续

分步能力已于 `2026-11-15 21:46 +08` 从固定 main `858a66c` 部署，验证与回退见[工作流发布记录](../deploy/parallel-test/releases/20261115-project-ai-workflow.md)。真实客户项目的完整交互和业务效果仍待验收。新建的工作重点分析、异常解释、周报、会议更新和措施跟踪按步骤保存进度；事实任务查询不调用模型，综合评估、组合财务和个人助手仍使用各自生成路径。旧分析记录继续可读，不会自动转成新工作流。

资料较少时一次分析后直接形成结果，不为展示步骤额外调用模型；长资料按记录和原文片段分批分析，再分层汇总。片段保留原始引用编号，汇总只使用已校验的阶段结论及真实来源，任务更新草稿由系统合并，不交给汇总模型删选。较长的备注、会议原文和变更记录完整分段；超过整体硬容量时明确拒绝，不静默裁掉资料。

界面显示「已完成 N / M 步」和当前步骤，可展开「查看已保存的阶段结果」。阶段结果尚未形成最终报告，不能当作全部事项已覆盖。最终报告可展开全部分段，周报复制与导出保留这些段落和原证据。只有最终结果通过结构、引用和操作字段校验后才提供报告；这种校验也不代表业务判断或会议提取必然完整，仍须人工核对。

已完成的步骤保存后不会因刷新或继续而重新生成。「暂停处理」保留进度；服务进程中断后，失效的处理中记录会转为已保存进度，未完成步骤可明确继续。如果上次模型调用的结果未知，继续可能重做该步骤，原调用的预算仍保留，不把未知用量当作零。旧记录的「停止整理」仍为终止本次旧运行。

「继续处理」在同一运行中开启新的处理窗口，只处理未完成部分，可能产生新的模型费用。同一账号同时只处理一项分析；重复点击继续或网络重试不会创建重复运行。继续前重新核对权限、原快照和模型设置，资料或配置变化时需按原要求新建分析，不能混用新旧步骤。相互冲突的任务更新会保留待核对内容并停止合并，不能默选一个值。硬上限或其他不可继续的原因会明确提示。

每个处理窗口最多 12 次模型请求、131072 tokens 的保守预留预算及 600 秒；整个运行最多 64 次请求、64 个步骤、2097152 tokens 的累计预留预算，拆分深度最多 6 层。预留预算含输入和输出空间，不等于实际账单；每次可能收费的请求发送前先保存预留，重启或继续不会清零。达到单窗口限制时保存进度，达到累计硬限时须缩小范围新建分析。新窗口不保证在一次等待中完成整个长任务。

常规首轮输出额度为 8192 tokens，异常解释或有界恢复为 16384 tokens；已识别的官方 Kimi 使用 16384 tokens。已识别的官方模型按场景使用低推理或关闭推理，未知兼容地址不附加供应商专用开关。截断、空正文、JSON 语法或必需字段缺失共用一次自动恢复机会，恢复调用同样计入窗口和累计预算；仍不完整的资料可在硬限内进一步拆分。恢复重新生成完整结构，不拼接残稿、不改写证据，权限、非法操作及冲突不能靠重试消除。旧的无工作流运行仍沿用最多两次请求、共 240 秒的有界恢复。

「查看诊断」按需显示最近步骤的请求额度、结束原因、耗时及服务商返回的 token 数；缺失数值显示「未返回」，不补为零，也不展示思维链。工作流累计请求数和预算另列，预算是保守预留值；实际返回用量不作精确计费凭据。刷新状态、展开诊断或查看历史不会请求模型。

会议中的同一任务更新可合并相同或互补字段并保留全部引用，字段冲突须人工解决。分步报告最多保留 768 条操作草稿；界面按最多 12 项分批核对，每批独立预览和确认，预览接口原有 20 项上限保持。查看报告、阶段结果或切换批次都不自动修改任务。

本地合成回归、真实模型的合成资料验证和生产验收分别记录；不以结构校验或单次模型返回宣称真实客户周报、全部会议动作或所有模型已经验收。部署后以新发布回执记录固定版本、数据库增列与回退边界。

## 历史与管理入口

「历史」按需展示本人有权访问的分析记录，以原问题或材料标题为主要标识；选择记录后才打开相应结果。「新问题」回到当前范围的输入入口。历史失败不自动带入新问题；可用「调整要求」带回原条件，或点击「重新整理」按原要求发起新运行。错误详情按需展开，失败结果不会标成成功。

明确要求项目综合评估或组合财务分析时，助手直接发起本次生成并只展示这份结果；进入旧深链或查看报告历史只读取，不自动重新生成。原综合评估报告保留后台状态、历史检索/分页、对比、导出与建议核对。综合评估沿用 `ai.analyze` 权限；「组合财务」仅向 `admin` / `cmc_lead` 在全部可见项目范围开放，单项目或任务页不隐式读取组合数据。「助手设置」沿用 `ai.config` 权限，维护组织共享模型及项目、财务提示词；门户 `/model-settings` 继续用于组织共享模型管理。

旧项目 `?tab=ai`、`agent_report`、`agent_proposal`、`aiRun` 链接保留；旧 `/ai-settings` 与 `/finance?tab=ai` 分别进入设置及组合财务。核对逾期报告保存后，继续在综合评估中打开这份报告。未知或不可访问的项目不会回退为全部项目。

## 上下文与证据

数据包含可见任务、关联依赖、项目日历、台账、变更、交付物目录和验收状态。交付物正文与附件文件不自动发送。普通成员的任务字段按职责裁剪，财务字段仅向具有相应管理权限的账号提供。

每条结论关联来源记录，可直接打开项目或任务。会议文字的引用展示原文段落。超过单次范围的资料有明确提示，可缩小范围后生成。历史记录只向发起人开放，读取时复核当前权限。项目事实或人员权限变化后应重新分析。

项目和任务页按分析时的实际范围查找历史记录。当前资料超出取数上限时，仍可查阅本人有权访问的历史结果，页面会提示无法核对数据变化。点击「调整要求」会带回原场景、实际范围、日期、问题和完整会议文字；可展开「调整日期」修改时间，重新发送时读取最新数据。历史组合范围超出当前项目或任务页时，会提示回到原范围继续，不能隐式扩展或缩小范围。「新问题」「退出调整」或选择另一条历史会清除这些待重用条件。

## 建议确认与核验

支持任务执行字段更新、新增任务，以及风险、问题和决策的新增与状态更新。草稿中的负责人、日期和记录对应关系由用户核对。缺少必要信息的草稿须补齐后才可预览。

模型提出更新已有记录时，需要引用目标记录。附有会议文字时，草稿还需引用本次提供的会议原文。

预览展示修改前后值。确认绑定当前用户、对象版本、完整差异及有效期。同一批次全部校验通过后一起写入，遇到冲突时重新预览。重复确认返回原回执。任务活动、台账变更和审计保留来源分析及修改依据。写入核验与后续任务完成、验收结果分别展示。

## 程序接口

- `GET /api/v1/pm-ai/context` 获取当前权限下的上下文。
- `POST /api/v1/pm-ai/agent/plan` 识别提问的项目、任务和处理方式。
- `POST /api/v1/pm-ai/agent/triage` 读取指定范围的任务事实，`task_filter` 支持 `attention`、`overdue`、`delayed`、`blocked`；默认 `attention` 保持原工作重点行为。
- `POST /api/v1/pm-ai/runs` 发起五类分析，`GET /runs` 和 `GET /runs/{id}` 查询本人记录。
- `POST /api/v1/pm-ai/runs/{id}/cancel` 暂停新工作流并保存进度；旧运行停止。
- `POST /api/v1/pm-ai/runs/{id}/resume` 在同一运行继续未完成步骤，重复请求幂等。
- `POST /api/v1/pm-ai/runs/{id}/changes/preview` 预览草稿，`POST /changes/apply` 确认执行。
- `POST /api/v1/pm-ai/schedule/compare` 比较结构化排期方案，使用既有排期确认接口执行选定方案。
- `GET /api/v1/pm-ai/tools` 获取机器可读工具目录。

以上接口使用已有 IAM 身份和业务权限。MCP 入口为 `/api/v1/pm-ai/mcp`，支持协议 `2025-06-18` 的无状态 JSON Streamable HTTP。客户端可携带已有有效 IAM Bearer 身份，浏览器访问继续检查可信来源。此入口提供上下文、生成分析、查询历史与取消工具，供用户在应用中核对草稿。身份凭据由客户端安全管理。

MCP 的 `pm_agent_plan`、`pm_work_priorities` 和 `pm_compare_schedule` 分别用于识别范围、读取重点和比较排期。排期比较使用已有管理权限，返回日期差异与冲突。用户可打开 `review_url` 查看任务并在应用中确认调整。

## 本地运行与升级

新增 `pm_ai_runs` 和 `pm_ai_change_receipts` 两张表，迁移号为 028。维护身份执行结构升级。新分析由 `PM_AI_WORKER_ENABLED` 控制，默认启用。独立测试环境可以关闭该工作线程，并通过测试夹具显式执行任务。

模型测试区分格式、证据校验和实际回答质量。自动测试覆盖权限、来源、版本冲突、撤销与重试；真实模型的内容质量结合业务数据验收。
