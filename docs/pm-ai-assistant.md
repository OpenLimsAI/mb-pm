# 项目 AI 助手

在项目工作台、项目详情或任务详情展开「项目 AI 助手」。界面使用当前账号的项目和任务权限，展示分析范围、数据时间、来源记录与待核对建议。模型由组织共享 AI 设置选定。

| 场景 | 操作与结果 |
| --- | --- |
| 工作重点 | 查询范围内任务和风险，结合期限、阻塞和状态生成重点事项及依据 |
| 异常解释 | 选择项目或任务，结合可见依赖、风险和变更解释现状与数据缺口 |
| 项目周报 | 选择日期范围，根据实际记录生成周报草稿 |
| 会议转更新 | 输入会议文字，核对引用段落、人员和任务，编辑待办或跟进事项草稿 |
| 措施跟踪 | 对照事项、任务与变更，区分已处理、仍待处理及缺少结果证据 |
| 排期比较 | 填写最多三个顺延工作日方案及固定节点，比较日期、冲突及当前页面数据估算的关键路径和负荷 |

分析在后台处理，关闭面板后可从本人历史中继续查看。可以取消排队或生成中的分析。取消后的结果不写入，已发出的模型请求可能已经消耗用量。服务中断的运行显示失败，由用户决定是否重试。

## 上下文与证据

数据包含可见任务、关联依赖、项目日历、台账、变更、交付物目录和验收状态。交付物正文与附件文件不自动发送。普通成员的任务字段按职责裁剪，财务字段仅向具有相应管理权限的账号提供。

每条结论关联来源记录，可直接打开项目或任务。会议文字的引用展示原文段落。超过单次范围的资料有明确提示，可缩小范围后生成。历史记录只向发起人开放，读取时复核当前权限。项目事实或人员权限变化后应重新分析。

## 建议确认与核验

支持任务执行字段更新、新增任务，以及风险、问题和决策的新增与状态更新。草稿中的负责人、日期和记录对应关系由用户核对。缺少必要信息的草稿须补齐后才可预览。

预览展示修改前后值。确认绑定当前用户、对象版本、完整差异及有效期。同一批次全部校验通过后一起写入，遇到冲突时重新预览。重复确认返回原回执。任务活动、台账变更和审计保留来源分析及修改依据。写入核验与后续任务完成、验收结果分别展示。

## 程序接口

- `GET /api/v1/pm-ai/context` 获取当前权限下的上下文。
- `POST /api/v1/pm-ai/runs` 发起五类分析，`GET /runs` 和 `GET /runs/{id}` 查询本人记录。
- `POST /api/v1/pm-ai/runs/{id}/cancel` 取消未完成分析。
- `POST /api/v1/pm-ai/runs/{id}/changes/preview` 预览草稿，`POST /changes/apply` 确认执行。
- `POST /api/v1/pm-ai/schedule/compare` 比较结构化排期方案，使用既有排期确认接口执行选定方案。
- `GET /api/v1/pm-ai/tools` 获取机器可读工具目录。

以上接口使用已有 IAM 身份和业务权限。MCP 入口为 `/api/v1/pm-ai/mcp`，支持协议 `2025-06-18` 的无状态 JSON Streamable HTTP。客户端可携带已有有效 IAM Bearer 身份，浏览器访问继续检查可信来源。此入口提供上下文、生成分析、查询历史与取消工具，供用户在应用中核对草稿。身份凭据由客户端安全管理。

## 本地运行与升级

新增 `pm_ai_runs` 和 `pm_ai_change_receipts` 两张表，迁移号为 028。维护身份执行结构升级。新分析由 `PM_AI_WORKER_ENABLED` 控制，默认启用。独立测试环境可以关闭该工作线程，并通过测试夹具显式执行任务。

模型测试区分格式、证据校验和实际回答质量。自动测试覆盖权限、来源、版本冲突、撤销与重试；真实模型的内容质量结合业务数据验收。
