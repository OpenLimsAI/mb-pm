# 备份清单宿主适配服务

本服务展示现有自动备份计划、统计已批准备份目录、核验已有完整归档，并在管理员逐次确认后删除选中的历史备份文件。显式启用后可调整单条已识别每日cron的时间、暂停或恢复。**不创建备份、不启停容器、不修改保留周期、不恢复数据库，也不执行自动清理。** 项目管理应用没有 Docker socket。

`catalogue_agent.py` 使用 Python 标准库；完整归档核验额外调用现有 GPG。所有运行配置、密钥、数据库和验证结果保存在服务器，网页只收到安全的元数据。此目录提供安装示例，不代表已经部署。

## 配置与运行

采用 `config.example.json` 结构。实际配置、HMAC secret 和 GPG key 必须为当前服务用户持有的私有文件（0600），状态目录0700。HMAC secret至少32字节，独立于GPG解密密钥，不能通过聊天或浏览器传递。

`roots` 是管理员批准的备份根目录，不重叠；必须逐个核对，不允许整个home或文件系统根目录。保留现有文件权限，不对客户目录执行chmod。遍历不跟随符号链接；只允许删除当前用户拥有、不可被其他用户写入的普通归档文件；硬链接始终保护。root目录不得全局可写；已有组可写目录可只读统计，其中归档一律保护。状态目录必须位于所有备份根目录之外。

`lockDirectory` 必须指向现有每日备份使用的目录，且两把现有锁文件可读写。删除会非阻塞获取 `.daily-backup.lock` 和 `.backup.lock`，备份/发布进行中拒绝删除。锁只协调遵守同一锁协议的程序，不替代服务器权限控制。

`planScript` 指向实际现有 `daily_backup.py`，只静态读取代码，不执行。计划来自当前服务用户的 `crontab -l`，时区来自系统或 `CRON_TZ`。读取失败、无法解析或多条冲突均明确展示，不把默认设置冒充现有计划。

`allowPlanChanges` 默认 `false`，旧配置保持只读；示例文件为 `true`。启用前保存原cron，安装同版代理、中继及其依赖模块（`health.py`）。管理员只提交每日时间、启停和计划修订号，代理在现有双锁内重新读取，拒绝旧版本覆盖，保留原命令、参数、环境、日志重定向和其他任务，安装后读回核对并记录私有审计。只允许单个已识别的每日任务和可确认的时区；缺失、冲突或自定义周期不开放编辑。暂停使用专属注释保留该行，恢复沿用原命令。`daily_backup.py` 会短时暂停业务写入，调整时间时应避开业务高峰。

默认监听127.0.0.1；允许显式指定宿主容器网关私有IPv4。若既有防火墙阻断容器到宿主端口，可设置 `unixSocket: true`：宿主只监听固定的 `stateDirectory/transport/catalogue.sock`（目录0700、套接字0600），不开放TCP。容器私网中的 `relay.py` 仅将固定清单、计划更新和删除请求原样转交给该套接字，HMAC仍由宿主核验，浏览器不能直连。

中转容器使用固定发布镜像的Python标准库，以UID1000运行，根文件系统只读、capabilities全关、no-new-privileges、限制CPU/内存/PID与日志；仅只读挂载套接字专用目录和同版relay.py。不能挂载状态数据库、解密密钥、备份根目录或Docker socket；不能使用host网络、不能发布宿主端口，只连接PM已有私有网络。宿主原防火墙无需调整。中转不持有凭据、不解析或修改业务正文、不重试删除请求，最多64KiB请求和2MiB响应。

不新增公开Tunnel路由，不开放浏览器直连。HMAC提供认证和完整性，不提供传输加密；通信留在已批准的宿主私有网络及私有套接字。

用户级systemd示例不需要sudo或额外Docker权限。只有明确批准的根目录可作为删除目标。安装时核对用户服务在重启后的可用性，并验证GPG、crontab读取、私网认证及目录权限。计划编辑只在管理员主动保存时修改对应每日任务，监控等其他cron保持原样。

## 显示与验证

容量按实际文件统计：备份占磁盘使用分配块数（硬链接去重）；归档大小为文件逻辑大小；其他材料是受管理根目录内不开放删除的材料。目录中的配置、密钥、日志和非归档文件不开放删除。

可列出完整 `maibo-时间.tar.gz.gpg` 和历史 `.tgz/.sql.gz/.dump/.sql/.tar.gz/.tar`；`.backup` 只在头部确认SQLite格式时列出。未知旧备份不根据文件名猜内容，显示“内容待确认”；创建时间无法可靠确认时显示未知。

后台串行核验完整GPG：直接通过管道解密，不落地明文；流式检查tar顶层普通文件、计算各payload的SHA256并比对实际manifest，**GPG成功退出后**才登记验证。只把真实manifest记录映射为项目管理/身份/知识库等安全内容类别，不返回环境变量、原始配置或内部路径。每份最多300秒，有文件数、大小及manifest内存上限。它证明归档认证与清单一致，不等于完成数据库恢复演练。

`health.py` 仅从清单生成提醒：计划停用、冲突或未知，完整已验证副本超过36小时，完整包无法读取，以及剩余空间不足10GiB或使用达到85%；不执行备份、清理或读取监控私有配置。归档返回稳定 `rootId`，支持前端按分类准确关联。

最新已验证的完整业务恢复副本始终保护（以实际归档清单范围为准，不宣称包含后来新增的服务）。历史独立备份按根目录、稳定子目录与归档名称识别同类，仅归一化明确的日期/时间及哈希后缀，每类最新一份也始终保护；不同应用的同名文件不会互为替代。尚未建立任何完整副本、备份锁被占用、硬链接、权限异常、正在扫描及尚未完成扫描的完整GPG均不能删除。普通旧归档仅在已建立完整恢复保护后才可手动选删。

## 私有 API

固定API为GET `/v1/snapshot`、POST `/v1/plan`、POST `/v1/delete-preview`、POST `/v1/deletions`。不接受任意路径、命令、下载请求、时区或保留策略修改。

计划更新请求：`{dailyTime:"HH:mm",enabled:boolean,revision:SHA256,actor}`；返回实际读回的计划，包括可编辑状态、每日时间、计划修订号、执行时区和下次执行时间。修订号绑定整份crontab，其他任务已被修改时也要求重新读取，避免覆盖并行修改。它不执行即时备份。人工直接修改crontab须与本管理串行；crontab命令无原子CAS，写前重读只拒绝已经观察到的外部变动，不能保证覆盖所有外部竞争。下次时间是墙上时钟的预估，夏令时补跑或跳过按宿主Cron实现执行。

签名头沿用 `X-Backup-Time`（Unix秒±60秒）、`X-Backup-Nonce`（新UUID hex）、`X-Backup-Signature`（HMAC-SHA256）。原文为METHOD、path、timestamp、nonce、sha256(body)五行，用换行分隔。nonce持久防重放；请求最大64KiB。PM后端注入真实actor，前端不能指定身份。

预览请求：`{archiveIds,catalogRevision,actor}`。返回五分钟有效token及精确数量、文件名、逻辑/磁盘大小。最多选100个，token绑定身份、清单版本和全部文件身份。

删除请求：`{token,confirmation:"删除 N 份备份",requestId:UUID,actor}`。双锁内先重新核对全部文件、保护副本和清单，然后仅对选中的文件逐个unlink；不删除目录，不递归删除。相同actor/requestId重复提交返回原回执；参数冲突拒绝。私有审计保留所选文件的标识、文件名、来源及文件身份。部分失败和进程中断保留审计并明确显示部分完成，不能自动重试删除其余文件。删除无法撤销，应先查看预览与保护提示。

测试：`python3 -m unittest discover -s deploy/data-backup/tests -v`。合成测试不接触生产、不调用Docker、不改变备份任务。

生产接入示例的后端地址为 `http://maibo-backup-relay:18941`，仅由同一Docker私网解析；具体固定镜像、安装与原cron保持证据写入当次发布记录。看护只重新启动清单服务，不执行备份或保留清理。

运行镜像不需要系统包管理器，移除APT及libapt；宿主GPG与备份工具保持原样，升级镜像不会卸载服务器软件。
