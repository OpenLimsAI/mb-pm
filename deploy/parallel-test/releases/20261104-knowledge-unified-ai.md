# 知识库统一 AI 与个人笔记恢复发布契约（2026-11-04）

代码准备发布，实际环境尚未切换；成功提交、镜像、备份和验收回执在部署完成后补充，不预称上线。

## 行为与范围

- 工作台 `/model-settings` 管理统一的个人模型与默认选择；知识库问答、翻译、摘要和标签通过服务端接口使用该配置，不复制模型密钥。
- PM 只接受知识库独立受众的已验证当前用户令牌，实时核对角色与账号状态；现有 PM／门户受众隔离保持不变。
- 仅笔记 HTML 路由 `/notes?embed=knowledge` 允许配置的精确知识库 Origin 嵌入；父子页面核对 Origin、窗口来源、协议版本和账号摘要，失败时可以重试或独立打开。
- 无运行依赖或数据库结构变更。沿用现有 `solution_ai_settings`、`personal_notes` 和修订号，不迁移或覆盖已有业务内容。
- 配套知识库发布修复问题集 Markdown 排版、跨账号旧页面请求、翻译并发／取消和部分回答失败处理；详见知识库仓库发布记录。

## 发布顺序

1. 基于最新 main 集成本轮差异，保留已经上线的助手输出恢复及其他功能。PR 最新提交全部 CI 通过后 squash，固定 main SHA 和源码树。
2. 按[安全发布与备份](../../security/README.md)执行服务器内加密备份、隔离恢复与候选验证。生产数据及凭据不复制到开发电脑。
3. 从固定提交构建 PM 完整前后端镜像，校验生产 API 标记、静态清单、匿名登录交互及最终镜像扫描；候选使用独立合成数据并关闭生产工作器。
4. 先部署兼容的 PM 网关与笔记页面，再部署使用统一网关的知识库。两端就绪后再核对模型目录和同账号笔记；不为验收自动调用客户付费模型。
5. 两个 PM 实例通过持久 Compose 覆盖启用 `KNOWLEDGE_AI_ENABLED=true` 和精确 `KNOWLEDGE_AI_CLIENT_ID`；沿用已确认的 `OIDC_GLOBAL_LOGOUT_ENABLED`、`CASDOOR_ACCOUNT_STATUS_VISIBLE`，保留 `KNOWLEDGE_NOTES_ORIGIN`。不复制知识库 client secret、不更换 APP_SECRET、不覆盖整个环境文件。
6. 保留实际容器标签的完整 Compose 序列、UID、安全限制、网络、卷、模型与其他环境配置。使用实际 daily 目录的双备份锁及发布锁，锁内重新核对容器 ID、镜像和配置摘要，并确认活动任务状态。
7. 只重建两个 PM 实例与配套知识库，不执行整栈清空或重新导入数据。失败时使用本次回执中的完整旧链及固定旧镜像回滚，保留数据库、知识库 SQLite/WAL 与新的业务写入。

## 验证与验收边界

需验证两个 PM 实例健康、匿名接口返回 401、`build-info.json` 与固定源码及最终静态包一致；检查个人模型、笔记、报告及助手内容保留。笔记页仅在指定路由和配置 Origin 下获得嵌入权限，其他页面仍受原策略限制。

合成回归可以验证受众、角色、错误、并发和传输契约，不能代替客户本人在实际浏览器完成统一登录、笔记查看和供应商生成验收。停止界面等待不保证已经发出的同步供应商请求立即终止，仍可能持续到单轮 120 秒超时。
