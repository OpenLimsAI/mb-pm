## 用户能看到的变化

本次围绕“问题能继续做、来源看得明白、失败知道怎么办”完善个人助手，保持新建任务、数据设置和任务搜索的简洁入口。

| 改进 | 使用方式与结果 | 本次边界 |
|---|---|---|
| 1. 停止生成与等待时间 | 生成期间显示已经等待多久，可点击“停止生成”；问题和已经生成的草稿仍保留 | 停止会阻止迟到的回答写入任务；已经发生的模型调用费用不承诺退回。尚未收到正文时没有可保留的草稿 |
| 2. 失败后的具体操作 | 按错误类型提供检查设置、缩小范围、重新生成或“接着草稿继续”，可复制诊断信息 | 只有确实保存了正文的未完成请求才能继续。续写会创建新的请求，仍需核对结果；不会自动反复调用模型 |
| 3. 更准确的知识库来源 | 区分库内来源材料数量、本轮列出的目录、检索命中、实际阅读和可核验引用；点击已记录的来源可查看原文 | 来源材料可能包含论文和监管资料，不能全部称为论文。引用数按正文中的明确路径核验；没有可靠材料分类时不猜测分类数量。原文查看读取当前授权版本，不是历史文件快照 |
| 4. 管理员故障诊断 | 在企业 AI 设置页查看“助手运行管理”，按诊断编号查找、查看失败类别及等待时间 | 仅实时核验通过的管理员可用；最近列表最多 50 条，默认统计最近 24 小时，排队及运行请求另计。面板不展示问题、回答、附件或密钥；不是自动告警或外部监控平台 |
| 5. 自动模式更容易纠正 | 改进追问和“不需要深入分析”等表达的判断，支持选择其他回答方式重新提问 | 自动判断采用明确规则，不能保证理解所有表达；用户仍可选择通用、知识库或联网方式。旧回答不会被悄悄改写 |
| 6. 发送前检查配置 | 先检查所选模型配置及本轮所需数据权限，缺少设置时给出具体提示 | 配置检查不发送生成或搜索请求；“配置完整”不等于外部服务已实测可用，网络、额度和上游故障仍可能在执行时发生 |
| 7. 保留未发送草稿和偏好 | 未发送的问题、附带资料及任务偏好按账号、环境和任务分开保存；可主动清空草稿 | 未发送草稿只保留在当前浏览器，7 天后过期；清除浏览器数据或存储失败会影响恢复。已经提交的问题仍按服务器持久请求恢复，不靠浏览器重发 |
| 8. 可维护的任务摘要 | 在任务设置中记录目标、术语和约定，也可从最近提问整理摘要后自行纠正 | 摘要最多 6,000 字，由用户确认，不在后台自动调用模型总结。整理提问不等于核验事实；同范围应用追问保留问题主题，但重新查询事实，不把旧应用回答或旧附件当作本轮证据 |
| 9. 长资料先预览再选择 | 文件解析后可选择本轮所需片段，保留提取正文的位置提示；过长资料不会直接截取后发送 | 本轮资料最多 20,000 字。片段位置是提取文本的字符位置，不承诺 PDF 页码或扫描件 OCR；未选择的片段不会发送 |
| 10. 更容易找到任务与最终成果 | 搜索任务名称、对话正文及附带文字，显示有权限的匹配片段；支持任务置顶、改名和选择最终成果 | 最终成果是用户明确选中的某条完整回答，不会删除其他对话和历史产物，也不代表 AI 内容已被核验 |
| 11. 历史、引用与权限一致 | 阅读历史回答、查看原文和继续草稿都按当前数据权限核对；受限任务仍可从列表删除或恢复 | 无法验证范围的旧项目回答继续受保护，不自动放开；可新建任务按当前范围重新提问。失去知识库权限后，正文和正文搜索结果不再返回 |
| 12. 队列和重复内容保留策略 | 管理员可设置每人待处理数、同时生成数及全局排队上限，减少单个账号占用全部处理名额 | 默认每人待处理 3、同时生成 1、全局排队 100；实际以运行配置为准。清理默认关闭，设置保留期后仍需管理员明确点击清理；每次最多 1,000 条，保留任务、完整回答、请求状态和诊断编号 |

来源提示与回答正文继续分开：通用回答直接回答问题，上方说明本轮是否使用应用数据和联网检索，不恢复内部字段或工具配置的技术性开场说明。保留 Enter 发送、Shift+Enter 换行、任务回收站、既有知识源完整工作流和 DeepSeek 搜索配置。
