# 参考论文导入知识源与研究现场提示（2026-11-03）

本记录定义本次发布范围和验证要求，实际版本、上线状态与回滚证据以发布后的回执为准；CI 通过不代表已部署。

## 行为

研究报告与个人 AI 助手的联网来源卡片可导入本人已保存回答中的论文标题及原始链接，分别归到「研究报告参考论文」「个人AI助手参考论文」。确认导入不自动下载；具备知识源管理及知识库写权限时，才可提交公开 PDF 下载、归档和按需索引。侧栏问答、行内问答及选中文字问答共用入口。保留重复导入/任务/原件复用、重试和知识源同标签页定位。

普通进入报告时静默恢复研究位置；未发送问题的恢复提示 5 秒后消失，未保存正文或中断提问仍保留明确提示。保留最新 main 的助手范围配置修复与可视编辑器布局更新。

使用步骤、权限与下载限制见[参考论文导入](../../../docs/reference-paper-import.md)。无公开 PDF 或访问失败时保留来源和错误原因，不把 HTML 作为 PDF 归档，不使用用户浏览器登录状态访问全文。

## 配套版本和顺序

- PM 从首次把本记录合入 main 的 squash 提交固定构建。
- 知识库配套 [PR #45](https://github.com/OpenDIKW/dikw-mbweb/pull/45) 增加明确的签名 `sourceKind: reference` 协议，保留默认 ICH 边界和实时角色、文件夹、PDF 与摘要核验。
- 先部署向后兼容的知识库接收协议，再部署 PM。只替换镜像，沿用容器标签中的完整 Compose 序列、真实身份、模型、搜索、持久卷、安全和资源配置；不执行数据库迁移、不更换密钥。

## 验证与保留

开发基线已完成前端、后端专项、知识库全量及独立浏览器预览检查，预览未产生真实 API、模型或下载调用；整合最新 main 后重新运行回归，并等待两个 PR 最新提交全部 CI 成功后 squash 合并。

发布前保存精确旧镜像、完整配置与私有备份；后台有进行中任务时延后切换，不强行中断业务。候选使用独立数据且禁用后台工作器。最终镜像静态文件和真实 API 构建参数逐项核对，公开及内部健康、匿名鉴权、知识库只读连接和原有数据保留分别记录。

回滚只恢复当前发布前的精确镜像与配置，保留本次和其后的业务数据、原件与索引；不以旧数据库快照覆盖新写入。两个应用共用备份/发布互斥锁，实际运行记录留在服务器私有发布目录，公开回执排除秘密及客户正文。
