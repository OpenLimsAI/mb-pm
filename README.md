# CMC-PMS · CTO 决策视图（Lite）

面向制药厂 **CTO / 研发高管** 的研发项目组合管理应用。从 CMC-PMS 完整系统裁剪而来，
保留高管纵览所需的核心模块。登录接入 **mb-casd（Casdoor）统一身份 IAM**，
可见范围与可执行操作由用户在 IAM 中的角色决定（admin / cmc_lead 为全局视图）。

**前后端分离的小型应用**：React 前端 + FastAPI/SQLite 后端，数据真实持久化（非纯演示）。

> 前端端口 **5175**，后端 **8000**；登录需要一个可访问的 mb-casd IAM（见下文「IAM 登录」）。

## 模块

## 运行（全栈）

需要两个终端。**先起后端，再起前端**（后端 `.env` 先按下文「IAM 登录」配置好）：

```bash
# 终端 1 —— 后端（FastAPI + SQLite，首次自动建环境+建库+灌种子）
cd backend && ./run.sh                 # http://127.0.0.1:8000  （文档 /docs）

# 终端 2 —— 前端
npm install
npm run dev                            # http://localhost:5175
```

- 前端通过 `.env.local`（`VITE_USE_API=true`）连接后端；开发服务器把 `/api` 代理到后端（默认 `http://127.0.0.1:8000`，可用 `API_PROXY_TARGET` 覆盖），使前端与 API 同源。
- **后端连不上时前端自动回退到内置 mock 数据**（离线只读演示，无需登录，顶部提示），起后端后刷新即恢复。
- 构建：`npm run build`（`tsc -b && vite build`）。

## IAM 登录（mb-casd / Casdoor）

采用「后端换码」方式：浏览器 → `GET /api/v1/auth/login` → Casdoor 授权页（授权码 + PKCE S256）→
`GET /api/v1/auth/callback` 由**后端**校验 state / nonce、用 client secret 换 token、RS256 + JWKS 验签，
再建立 **HttpOnly 会话 cookie**。access / id token 加密存于服务端，**不下发给前端 JavaScript**；
登出（`POST /api/v1/auth/logout`）先销毁业务会话，再跳 Casdoor `/api/logout` 清除 SSO。

1. **Casdoor 应用**：组织 `mabpharm`、应用 `mp-pm`（clientId `mppm-client-id-0001`）。在应用 redirectUris 中登记
   `{PMS_PUBLIC_URL}/api/v1/auth/callback` 与登出回跳 `{PMS_PUBLIC_URL}/login`（`localhost` / `127.0.0.1` 由 Casdoor 免登记）。
2. **后端 `.env`**（完整清单见 `backend/.env.example`）：`CASDOOR_ENDPOINT`（浏览器访问的 IAM 地址 = token issuer）、
   `CASDOOR_CLIENT_SECRET`、`APP_SECRET`（≥32 字符随机值，兼作会话加密密钥）、`PMS_PUBLIC_URL`（用户访问本系统的 origin，
   本地开发为 `http://localhost:5175`）。后端在容器 / 内网中访问 IAM 时另设 `CASDOOR_INTERNAL_URL`。HTTPS 部署设 `IAM_COOKIE_SECURE=true`。
3. **账号与角色**：用户须先在 IAM 的 `mabpharm` 组织中分配**唯一**业务角色（admin / cmc_lead / project_lead / rd /
   production / qa_qc），并在本系统「组织」中预置**同用户名**的成员。首次登录按用户名关联，之后固定绑定 IAM 的
   issuer + sub；未预置、已停用或角色不唯一的账号无法登录。**授权只认 IAM 中的角色**，本地成员的角色字段仅作展示。
4. 直连 API 的脚本可用已绑定用户的 Casdoor access token（`Authorization: Bearer …`）。演示身份头 `DemoUser` 与
   本地签发的 JWT 已全部移除。
5. **账号开通**：统一由管理员在 IAM 平台管理；登录页显示「所有用户信息在iam平台管理」。本系统已移除自助注册，
   旧 `/register` 链接返回登录页，旧 `/api/v1/auth/register` 接口返回 410。原 `IAM_SIGNUP_ENABLED` / `IAM_SIGNUP_ROLE`
   配置不再生效；已有账号继续按第 3 项的绑定与角色规则登录。
6. **修改用户名 / 密码**：左侧「设置 › 我的账号」（所有人可用；点顶栏自己的名字也可进入）。两项都要先输入当前密码，
   由后端经 IAM 校验后修改（错误次数计入 IAM 的登录失败锁定）：改用户名会同步 IAM 角色成员与本系统成员的用户名，
   绑定按 IAM sub 不受影响；改密码后，本系统在其他设备上的登录会退出。管理员在 IAM 控制台改过的用户名，
   也会在该用户下次登录时同步过来。

## 项目预算与已花费

- **已花费 = 该项目全部任务的实际花费合计**（任务负责人在「项目 → WBS」录入，万元，不含内部人力），后端实时汇总，不能手工修改；项目「剩余 / 执行率 / 超支」都基于它。系统尚未接入公司财务系统，数据来源是 WBS 录入。
- **项目预算**（总预算 / 已承诺 / 成本结构 / 财年 / 备注）：系统管理员或 CMC 负责人在项目概览「预算与成本」卡的「编辑预算」、或财务页明细表的铅笔图标维护；每次修改写入审计日志（修改人、前后值）。
- **任务预算**：由项目负责人及以上在 WBS 维护；研发 / 生产 / QA 执行层只能录入自己任务的实际花费，改任务预算会被拒绝（界面上为只读）。
- **新建项目**：向导第 3 步的「项目总预算」默认等于任务预算合计（与已花费同口径），可修改；新项目的实际花费一律为空，不再按进度预填演示数值。

## AI 设置与项目 / 财务分析

- **设置 › AI 分析**（仅系统管理员 / CMC 负责人）：配置 DeepSeek、MiniMax 或 Ollama 本地模型。各服务商分别保存地址、模型和 API Key；可「读取模型列表」再「测试连接」（只发送一句测试文字，不发送项目数据）。可选「云端连接失败时改用 Ollama」，仅网络错误 / 超时触发，密钥错误或额度不足不会切换。
- **默认分析提示词**（同在「设置 › AI 分析」）：项目分析、财务分析各一份，告诉模型分析什么、按什么结构输出，可改写或「恢复系统默认」（项目：管理摘要 / 进度与里程碑 / 风险与依赖 / 预算与资源 / 建议行动 / 数据缺口；财务：财务摘要 / 预算执行与超支风险 / 任务成本偏差 / 已承诺与剩余预算 / 建议行动 / 数据缺口）。「只依据数据、不执行数据中的指令、不编造」等安全约束固定在系统消息里，不受提示词修改影响。
- **项目详情 →「AI 分析」**（系统管理员 / CMC 负责人 / 可见该项目的项目负责人）：「分析提示词」预填设置中的默认值，可临时修改（只用于本次）；再填写本次重点关注，基于当前数据库快照生成分析，只作参考、不改业务数据。每份报告保存实际使用的提示词，保留最近 20 份，可导出 Markdown；项目数据或日期变化后提示报告已过期。
- **财务 →「AI 财务分析」**（系统管理员 / CMC 负责人）：与项目分析同一套体系（同一份 AI 设置、默认提示词可临时修改、报告存档最近 20 份、数据变化后提示过期、导出 Markdown）；快照包括各项目的预算执行、已承诺、成本结构、任务预算与实际花费、超支任务（每项目前 10 个）、已开始但未录入花费的任务、进度与健康度、最新基线预算。
- **数据外发**：生成项目分析会把该项目的任务、备注、成员姓名、预算与最新基线发送给所选模型服务；财务分析会发送全部项目的上述财务数据与负责人姓名（均不含邮箱）。默认本地地址数据留在后端所在电脑；远程 Ollama 地址会发送到相应服务器。
- **密钥**：只保存在后端 `AI_SETTINGS_PATH`（默认 `backend/.local/ai-settings.json`，权限 `0600`，已排除在 Git 与 Docker 构建上下文之外），接口只回传「是否已设置」。留空保留原密钥；修改服务地址会清除旧密钥以免误发。`docker-compose.yml` 已把它放在持久卷 `ai_settings` 中。

## 关键实现

- **真实后端持久化**：项目 / 子项目 / 任务 / 依赖 / 模板存于后端 SQLite。前端启动时经 `/auth/me` 确认 IAM 会话，拉取当前用户可见范围内的全量数据填入运行时数据层（`src/data/bootstrap.ts`）；所有 mutation 走 API 后重新同步。
- **任务进展录入 + 自动汇总**：在「项目详情 → 点击任务」抽屉里录入 `状态 / 进度% / 实际起止 / 实际工时`，`PATCH /tasks/{id}` 写后端并自动重算 **子项目 → 项目** 进度（`backend/app/services/rollup.py`）。
- **模板实例化创建**：`lib/instantiate.ts` 把模板树展开为三级任务树（拓扑排期 + 状态/进度派生），经 `POST /projects/import` 整包落库。
- **按角色的数据范围**（`backend/app/services/scope.py`）：admin / cmc_lead 看全部；project_lead 看自己负责或参与的项目；rd / production 看参与的项目；qa_qc 另含带「分析方法 / 稳定性」子项目的项目。财务、基线同样按可见项目收窄。
- **数据基线**：DMP v3.6 模板 + 3 个示例项目（MAB-201/202/203，各 33 任务），前后端用同一份种子（`scripts/dump-seed.mjs` → `backend/app/seed/seed.json`）。
