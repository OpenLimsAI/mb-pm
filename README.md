# CMC-PMS · CTO 决策视图（Lite）

面向制药厂 **CTO / 研发高管** 的研发项目组合管理应用。从 CMC-PMS 完整系统裁剪而来，
保留高管纵览所需的核心模块，支持现有 IAM 登录；尚未启用 IAM 时保留原有 CMC 负责人演示入口。

**前后端分离的小型应用**：React 前端 + FastAPI/SQLite 后端，数据真实持久化（非纯演示）。

> 前端端口 **5175**，后端 **8015**。

## 模块

| 模块 | 路由 | 作用 |
|------|------|------|
| **首页** | `/` | 项目组合总览：组合 KPI（在研项目 / 总进度 / 待达里程碑 / **风险项** / 关键路径 / 预算执行）、**风险预警**（拆分为「进度风险」与「质量与合规风险」两族，质量门里程碑可派生、偏差/CAPA/批次留有接入位）、项目健康度红黄绿分组卡片。 |
| **项目** | `/projects` | 项目列表（卡片 / 表格 / 组合矩阵）+ 右上角 **模板管理** 入口（→ `/templates`：模板目录 / 新建（空白·复制）/ 可视化结构编辑器 / 甘特预览 / 导出 / 删除）+ **从模板创建项目**（向导第 3 步可增删任务）+ 项目详情：**概览**（里程碑路线图 + **预算与成本卡**）、**WBS**（行内编辑表格 / 树 / 甘特，状态·进度·计划起止·**负责人改派**·**任务预算**均行内即改即存并汇总）、**里程碑**（达成条件 ↔ WBS 任务关联）、**基线对标**、**团队**（成员管理，仍负责任务时拦截删除）。 |
| **财务** | `/finance` | **组合预算与成本中心**：组合 KPI（总预算 / 已花费 / 已承诺 / 剩余 / 执行率 / 超支）+ 预算执行 + 成本结构（按类别）+ 超支项目 + **分项目预算明细表**（项目级预算执行 + WBS 任务预算合计，自下而上来自模板 costBudget）。 |
| **组织** | `/org` | 组织成员目录 + **增删成员**（新增、停用/启用、删除——仍负责项目/任务的成员受引用守卫保护）。 |

## 运行（全栈）

需要两个终端。**先起后端，再起前端**：

```bash
# 终端 1 —— 后端（FastAPI + SQLite，首次自动建环境+建库+灌种子）
cd backend && ./run.sh                 # http://127.0.0.1:8015  （文档 /docs）

# 终端 2 —— 前端
npm install
npm run dev                            # http://localhost:5175
```

- 前端通过 `.env.local`（`VITE_USE_API=true`）连接后端。
- API 或登录失败会显示错误，不会自动回退为高权限演示用户。仅显式配置 `VITE_USE_API=false` 时使用内置 mock。
- 构建：`npm run build`（`tsc -b && vite build`）。

## AI 设置与项目分析

- 左侧「设置」配置 DeepSeek、MiniMax、OpenAI、自定义 OpenAI 兼容 API 或 Ollama。本次服务使用前端 `5175`、后端 `8015`（原 `8000` 已占用）。
- 各服务商分别保存基础地址、模型和 API Key。可读取模型列表、手动输入模型，再用「测试连接」执行一次简短对话；测试不会发送项目数据。预填模型沿用月报系统，实际可用模型以服务商返回的列表为准。
- Ollama 默认地址 `http://127.0.0.1:11434`，无需密钥。先自行运行 Ollama 并安装模型，再读取模型列表。自定义兼容 API 可连接 LM Studio 等服务，基础地址通常以 `/v1` 结尾。
- 可选「云端连接失败时改用 Ollama」；仅网络错误/超时触发，报告注明实际使用的模型。不会因为密钥错误或额度不足自动切换。
- 项目详情 →「AI 分析」：可填写关注事项，生成进度、里程碑、依赖、预算、资源、风险与行动建议。分析读取当前数据库快照，不修改业务数据；显示最近 20 份记录，支持 Markdown 导出，源数据或日期变化时提示报告已过期。
- 生成时会发送该项目的任务、备注、成员姓名、预算与最新基线到所选模型服务。默认本地地址把数据留在后端所在电脑；远程 Ollama / 自定义地址会发送到相应服务器。
- 密钥只保存在后端 `.local/ai-settings.json`（权限 `0600`），接口只回传「是否已设置」。留空保留原密钥，修改服务地址会清除旧密钥以避免误发；设置页提供显式清除功能。该文件排除在 Git 和 Docker 构建上下文之外。部署时用 `AI_SETTINGS_PATH` 指向持久化、受保护的目录。不会读取月报系统的密钥。
- 设置仅限管理员 / CMC 负责人；项目分析限管理员 / CMC 负责人 / 有项目访问权限的项目负责人，沿用现有登录体系。首次启动自动创建分析记录表。

本机运行（使用独立 Python 环境）：

```bash
cd backend
.venv-runtime/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8015
# 另一个终端，在项目根目录：
npm run dev  # .env.local 使用 VITE_API_URL=/api/v1，经 Vite 代理到 8015
```

## 关键实现

- **真实后端持久化**：项目 / 子项目 / 任务 / 依赖 / 模板存于后端 SQLite。前端启动时按配置加载 IAM 会话或 CTO 演示 JWT，拉取全量数据填入运行时数据层（`src/data/bootstrap.ts`）；所有 mutation 走 API 后重新同步。
- **任务进展录入 + 自动汇总**：在「项目详情 → 点击任务」抽屉里录入 `状态 / 进度% / 实际起止 / 实际工时`，`PATCH /tasks/{id}` 写后端并自动重算 **子项目 → 项目** 进度（`backend/app/services/rollup.py`）。
- **模板实例化创建**：`lib/instantiate.ts` 把模板树展开为三级任务树（拓扑排期 + 状态/进度派生），经 `POST /projects/import` 整包落库。
- **IAM 账号**：接入现有 Casdoor 的注册、登录、个人账号管理；新注册用户默认最低研发角色，未分配项目时无项目访问权。启用步骤见 [IAM 账号接入](docs/IAM账号接入.md)。现有管理员和郭主任身份保留。
- **数据基线**：DMP v3.6 模板 + 3 个示例项目（MAB-201/202/203，各 33 任务），前后端用同一份种子（`scripts/dump-seed.mjs` → `backend/app/seed/seed.json`）。
